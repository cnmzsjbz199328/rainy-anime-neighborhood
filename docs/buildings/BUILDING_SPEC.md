# 建筑构建规格 v1：雨夜手绘漫画小城

本包将最初便利店提示词的细节密度扩展到冻结布局中的全部 38 个地块。它是下一阶段的设计与实施依据，不表示建筑已经实现。35 个预留地块获得逐栋任务卡，3 个已有样板获得保留与后续升级任务卡。当前道路保持不变。

## 阅读顺序与约束优先级
1. 仓库 AGENTS.md（若存在）、PROGRESS.md、docs/layout/LAYOUT_V1.md 和实际 layout.js。
2. 本文件、BUILDING_QUEUE.md、catalog.json。
3. tasks/<地块ID>.md、references/<地块ID>.jpg 和 IMAGE_PROMPTS.json。

尺寸、入口、朝向和最高点：实际 layout.js > 任务卡 > AI 参考图。外观：本规格与任务卡 > 参考图。参考图是概念设计，不能据其猜测精确坐标；跨视图不一致时采用任务卡结构说明，记录选择。所有任务卡的数据来自布局 v1。实施前重新读取 main，如边界更新则停止该栋放置并报告差异，不能用旧坐标覆盖新布局。

## 核心视觉提示词
构建可自由旋转、拖动、缩放的真实 Three.js 日式邻里微缩世界。保留现有 96×96 方形底座和第三人称观看方式，无屏幕 UI、无人物。每栋建筑像精致收藏模型，具有可从四面观看的墙体、屋顶、雨棚和设备，以及真实厚度、分层楼板、内外过渡。

视觉采用“3D 渲染得像 2D”的赛璐璐明暗，并融入后来确定的手绘漫画风：深蓝灰或深褐墨线、轻微不规则线条、克制纸纹、水彩淡洗、低饱和柔色；不要让线条每帧随机抖动。纹理干净、细节丰富但不嘈杂。建立建筑之间的高低、屋顶轮廓、立面节奏和材料差异，保持同一城市的美术语言。

雨夜外部以冷蓝、灰紫与潮湿石灰色为主，内部以柔暖黄、琥珀或奶油白照明。玻璃能看见有用途的室内：货架、工作台、家具、动线和后勤空间，而非发光空盒。住宅只让部分窗户亮灯；公共建筑按用途控制灯光，不能每扇窗同等明亮。便利店仍是主要暖光视觉锚点，新增建筑不得用过强灯光抢走中心。

无人物但有生活痕迹：雨伞架、邮箱、分类垃圾、自行车、摆放整齐的商品、轻微水渍、公告或店招。真实功能与安静温暖的 slice-of-life 气氛优先，避免废墟感、巨大霓虹广告、统一复制立面和过度磨损。

## 外部建模标准
- 正面、背面、左右侧和屋顶都要完成；设备和后勤主要放侧后方，不能让后面成为无细节白墙。
- 从地面到屋顶有完整构造：地坪、基座、墙厚、门窗洞口、屋顶厚度、檐口、落水管、设备支架。
- 招牌采用原创店名/图形，文字可用 CanvasTexture；图片里不可靠的文字不能直接当成标牌资源。
- 前门接既定入口；所有花盆、售货机、台阶、檐角、空调和自行车都计入占地检查。
- 车辆与自行车通路不挤占公共人行道；不重新生成路灯、电杆、斑马线或道路底座。
- 不额外给每栋加独立方形模型底座。参考板中的展示地面，在实现时并入现有地块地坪。

## 内部与楼层标准
- 每种建筑有明确前场、工作区/生活区、后场与储物，而非统一家具模板。
- 窗外近景至少能辨认 3 层深度：靠窗陈列/家具、中部通路、后部设备或隔墙。
- 楼房有真正楼板、楼梯、各层隔墙和不同功能；学校包含主翼、低翼与院落，不是超大单盒。
- 新建商店净层高建议 2.7–3.1，住宅 2.6–2.9，学校 3.0–3.3；计算楼板/屋顶厚度后不得超过 maxHeight。这些是模型设计参考，不是建筑法规。
- 门净高建议 2.0–2.2，柜台 0.85–1.05，椅座约 0.42–0.48；模型尺度参照新建标准和整体场景。已有样板夸张比例不得向全城扩散，也不顺便缩放现有样板。
- 室内主通路建议至少 0.9，公共入口建议至少 1.2；受小地块约束时优先减家具数量，不缩成玩具比例。精确入口与车辆区先按实际布局确定。
- 外部模式保持完整屋顶。INTERIOR 图仅用于参考，可通过开发截图临时隐藏屋顶验证，不因此新增可见 UI 或自动切屋顶交互。
- 模型不只是贴照片：窗、门框、主要柜台/家具和功能设备必须有真实几何；重复小商品可用贴图、实例或合批。

## 材质、照明与动画
沿用现有 toon/墨线/纸纹工具；先读 scene.js 的材质、分组与动画方式。共享材质/纹理，避免一个商品一个材质或光源。窗玻璃不能成为不透明蓝色板，透明层排序和背后家具可见性要实际截图验证。采用 emissive + 烘焙/贴图光斑表现大量窗灯，新增实时灯前必须说明性能成本。

细微动画只在需要的建筑启用：檐水、窗雨、暖光微变、咖啡或厨房极淡蒸汽、植物轻摆。洗衣机低速滚筒；便利店已有自动门保持既有节奏。每栋至多 1–3 处主要局部动画，稳定亮灯比持续频闪更适合安静雨夜。不重复创建全局降雨与街道水洼系统。

新建筑屋顶必须登记进现有遮雨计算。确认 scene.js 的遮雨区是否仍只取 samples：若是，扩展为统一建筑注册表，同时保留 samples；不能通过把新建筑错误标为旧样板来绕过。檐水接建筑自有排水，倒影落在可见湿地面，不穿墙、不悬空。

## 数据和代码集成
- layout.js 保持唯一地块来源。新建筑的局部坐标前方约定为 +Z；映射 N=π、S=0、E=π/2、W=-π/2（Three.js 绕 Y）。若当前项目已有不同约定，复用项目约定并记录。
- 记录主体、附属设施和步行高度占地的包围盒；检查本地到世界变换后的真实占地、最高点和入口接线，不只验证建议尺寸。
- 建筑按地块 ID 分组/注册。若拆新源码文件，必须同步 build.py 的嵌入顺序和 index.html；保持最终单文件 HTML 可以打开，不依赖外网 CDN。
- 新增文件应在本项目内复用工具，不另起框架。不能只提交源文件而忘记重新生成 index.html。
- 图像是开发参考，不作为全屏背景或平面广告牌来冒充 3D 建筑；不嵌入所有参考板到运行 HTML。

## 统一验收
每栋先规划、再粗模、再细化、再集成；每个实现提交附上：
1. 真实主体/附属设施包围盒与占地、入口和高度检查。现有 C1–C11 继续通过，并让新建筑参与检查；C11 的候选试排不能代替真实模型验收。
2. 首帧成功，浏览器控制台无新增错误，旋转/缩放/平移正常，离线打开无缺失脚本/资源。
3. 开发截图：正面、背面、左右侧、屋顶俯视、室内剖视、雨夜前右及后左。默认街角与全城远景各一张，确认邻栋不遮挡便利店主要窗面。
4. 雨不穿屋顶，窗后家具可见，台阶/花盆/设备落地，透明面不闪烁，门开启不碰家具。
5. 记录新增几何数、材质数、绘制调用/纹理负担及同视角性能变化。软件 WebGL 结果只能代表本环境；真实 GPU/手机/iPad 缺测须保留待验证，不虚报通过。
6. 更新 PROGRESS.md、任务状态和截图路径，说明修改地块、实际尺寸、未完成细节与验证命令。

## 首个实施范围
先只实现 B05-P03 雨宿咖啡店。验收通过后实现 B05-P04 花店。其余地块仍空置，现有便利店/拉面店/公寓不顺带重建。学校排最后，先积累多层和公共建筑经验。
