# S3 精确规格：升级便利店 B05-P01（こもれび MART）

状态：生效，供 [SAMPLE_UPGRADE_AGENT_START.md](SAMPLE_UPGRADE_AGENT_START.md) 的 S3 一轮使用。通用流程、风险和验收门槛见 [SAMPLE_UPGRADE_PLAN.md](SAMPLE_UPGRADE_PLAN.md)；本文只写便利店特有的事实与要求。S1（拉面店）、S2（公寓）的实施记录是可参照的先例，先读。

## 1. 为什么单独写

便利店是全城暖光视觉锚点，也是旧样板里耦合最多的一栋：它的动画、灯光倒影和附属物散在 `scene.js` 多处，退役时稍有疏漏就会丢功能或报错。

## 2. 现状清单（来自 scene.js 与基线，均须在新版中有对应物）

| 项 | 旧实现位置 | 新版要求 |

## 3. 放置与尺寸

- 门世界坐标 (−12.34, 23.20) 不变，冻结入口 (−12.34, 21) 不变；用局部原点为门心，反算 `transform`，用 `tools/frozen_diff.mjs` 逐位核对。
- 可建包络 [−16.5, 22, −7, 29.5]（9.5 × 7.5）。旧主体约 7.49 × 6.58，附属另计；新主体可略加深以容纳后场，但雨棚、檐口、空调、落水管全部计入包络。
- 旧主体最外缘距包络约 0.4–0.7（北侧约 0.4），新版不要更贴。
- 层高与家具按新建筑标准：门净高 2.0–2.2，收银台 0.85–1.05（旧版 1.58 偏高），货架高度按真实便利店比例。身份与配色保留：淡奶油墙、青绿与珊瑚色灯带、深灰平屋顶。
- 屋顶放入 `userData.layer = 'roof'` 分组，使剖视截图能移除；设备（空调、水箱）也在该层。

## 4. 视觉锚点要求（可测量）

1. `town.png`、`default.png` 与基线相比，便利店窗区的平均亮度不低于基线的 90%，且全城没有其他建筑的窗亮度高于它（目视加对比图）。
2. 招牌仍是该街景最亮的文字元素。
3. 不新增实时光源；点光源总数不增加。
4. 夜景冷暖对比：外部冷蓝，室内柔暖，不做发光空盒，窗后三层深度（近处货架、中部通路、后部冷柜/后场）清晰。

## 5. 参考图使用

`docs/buildings/references/B05-P01.jpg` 是升级概念：绿橙条带、绿色雨篷、屋顶双空调与管线、后门加两台空调与周转箱、东墙条形窗、右侧后勤空调与电箱。图中店名与「24」是不可靠文字，不作资产，保留 こもれび MART 与现有文案。图与任务卡、layout.js 冲突时，以后两者为准，并在任务卡记录裁决。

## 6. 工作顺序

1. 先读 S1、S2 的实施记录与 `buildings/B05-P02.js`、`buildings/B05-P05.js` 的做法，沿用同样的登记、退役和守卫方式。
2. 粗模外壳与雨棚，`python3 build.py` + `node tools/measure_samples.mjs` 实测，确认在包络内。
3. 登记并退役旧便利店（含 `doors`、`sign`、`drops`、`drips`、倒影、落水管、`vending`、`bicycles`、`storeProps`），确认页面无错误。
4. 细化外观四面、室内、动画；逐项对照第 2 节清单勾选。
5. 全部门槛通过后合并 main，不推送。

## 7. 验收（在 SAMPLE_UPGRADE_PLAN 第 6 节门槛之外）

- 第 2 节每一行都有对应实现，并在任务卡实施记录里逐行列出「继承 / 改进 / 取消及理由」；**不允许无理由取消**。
- 第 4 节四条全部满足，附对比图路径。
- 绘制调用增量目标 ≤ +250（拉面店 +142、咖啡店 +179 作参照；旧版 +1180 因未合批，新版预期大幅下降）；超出须说明。
- `frame()` 中引用已退役对象的代码保持无错（S4 才清理）。
- `building_views` 的局部动画探针非 0（旧样板为 0/1，新版应能检测到门、招牌、雨痕等变化）。

## 8. 停止条件

在 SAMPLE_UPGRADE_PLAN 第 9 节之外增加：新主体在包络内无法同时容纳后场与雨棚，且只能靠移动门或缩小身份特征解决时，停下报告，不自行取舍。
