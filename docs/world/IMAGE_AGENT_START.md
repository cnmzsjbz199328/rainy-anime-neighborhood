# 星球参考图生成提示词（图像 Agent 通用模板）

你是本仓库的参考图生成 Agent，负责为星球设计卡生成概念参考图。你需要具备图像生成能力。每一轮按用户指定的卡片生成参考图、逐张审查、记录结果并提交。不要只返回计划。

## 如何使用本模板

每轮只需给 Agent 一句话：

> 读取 docs/world/IMAGE_AGENT_START.md 并执行，本轮卡片：ST01。

- 可以一次指定多张，例如"本轮卡片：BI01–BI09"。
- 用户没有指定时，按下方"生成顺序"取下一批 `referenceStatus: "pending"` 的卡片，并在开始时说明选了哪些。
- **ST01 必须第一个生成，并在用户确认风格后才能继续其他卡片。** ST01 是所有参考图的风格基准。

## 先读

1. [WORLD_PLAN.md](../../WORLD_PLAN.md)，尤其是第 3 节"已确定的决策"和第 4 节"天气"。**如果用户已经修改了某项决策，但设计卡和 IMAGE_PROMPTS.json 还没有同步更新，停下来报告，不要按旧内容生成。**
2. [WORLD_SPEC.md](WORLD_SPEC.md)：色板、三个观看距离、墨线规则、光与天气、动态规则。
3. 本轮每张卡片的 `cards/<ID>.md`，以及 [IMAGE_PROMPTS.json](IMAGE_PROMPTS.json) 中对应的 `prompt`。
4. 城镇的风格参考（必须看图，不能只读文件名）：
   - [docs/buildings/screenshots/B05-P03/](../buildings/screenshots/B05-P03/) 中的实景截图，尤其是 `default.png`、`town.png`、`frontRight.png`；
   - [docs/buildings/references/B05-P03.jpg](../buildings/references/B05-P03.jpg) 等城镇建筑参考板，了解现有参考图的版式和画风。
5. ST01 生成并确认之后，其余所有卡片都要先看 `references/ST01.jpg`；地貌和过渡带卡片还要看 `references/ST03.jpg`（如已生成）。

## 每张卡片的生成步骤

1. **提示词**：使用 IMAGE_PROMPTS.json 中该卡片的 `prompt` 原文。
   - 如果你的生图工具支持参考图输入：附上 `references/ST01.jpg` 作为风格参考（ST01 本身除外）；地貌和过渡带再附上 `references/ST03.jpg`；地标可以附上城镇建筑参考板作为画风参考。
   - 如果提示词太长、超过工具限制，可以删去其中的中文说明句，但必须保留英文的版式描述（格数、标签、每格内容）和 `Must avoid` 部分。实际使用的提示词要记录在 REFERENCE_REVIEW.md。
2. **生成**：每张卡片一次独立生成，横版，不小于 1536 × 1024。
3. **保存**：保存为 `docs/world/references/<ID>.jpg`。JPEG 质量 92，不做色度子采样，不裁剪任何一格。
4. **审查**：直接查看生成的图片，按下方清单逐项检查。
5. **重试**：审查不通过时调整提示词重新生成，每张最多 3 次。3 次都不理想时，保留最好的一张，把问题写进审查记录，交给实施阶段裁决。
6. **记录**：按"文档更新清单"更新。

## 审查清单

每张图都要检查：

- [ ] 格数和标签与卡片"参考图要求"一致；每格内容对应正确的标签。
- [ ] 所有格子展示的是同一个设计：同样的形状、尺寸关系、材质和颜色。
- [ ] 画风符合 ST01 和 WORLD_SPEC：墨线、水彩淡洗、赛璐璐明暗、低饱和；不是写实照片，不是平面地图。
- [ ] 色板符合 WORLD_SPEC：暖光只来自卡片允许的光源；隐藏线索的光是极淡的冷青白。
- [ ] 尺度合理：人造物（门、台阶、栏杆、长椅）保持真实人体尺度；地形高度可以夸张。
- [ ] 夜间格子符合卡片"夜间光照"和"局部天气"的描述。
- [ ] 所有星球全景格（GLOBE、GLOBE NIGHT、GLOBE CLEAR 等）都是晴朗月夜：无雨、无遮挡地表的云层，月光明亮，地貌和道路清晰可见，但不能画成白天。
- [ ] 卡片"约束与禁止"里的内容都没有出现；没有人物、动物（萤火虫除外）、移动的车辆、水印或多余文字。
- [ ] 地貌卡：MOTION 格能看出卡片描述的动态。
- [ ] 过渡带卡：交界是渐变、不规则的，没有直线硬边。
- [ ] 道路卡：GLOBE NIGHT 格的灯光与卡片一致（有灯或无灯）。
- [ ] 地标卡：FROM AFAR 格表现出小星球强烈弯曲的地平线。
- [ ] 隐藏线索（LM05、LM06、LM07）：第一眼必须读作古代遗迹、废弃车站或冰原，线索只能隐约可见；不能出现飞碟、外星人或科幻发光纹路。

## 文档更新清单

- `cards/<ID>.md` 的"参考图审查记录"：
  - `referenceStatus: generated`（审查通过）或 `generated-with-issues`（3 次后仍有问题）；
  - `reviewer:` 写明生成工具和日期；
  - `notes:` 写明与卡片不一致的地方，以及建议实施时如何裁决。
  - "状态与关联"中的"参考图待生成"改为"参考图已生成"，参考图路径改为可点击的链接：`[参考图](../references/<ID>.jpg)`。
  - 卡片的设计内容（外观、尺度、约束等）**不要修改**。如果你认为设计本身有问题，写进审查记录，交给用户决定。
- [catalog.json](catalog.json)：本条的 `referenceStatus` 改为 `generated` 或 `generated-with-issues`。只改本条，保持原格式。
- [cards/README.md](cards/README.md)：本卡一行的"参考图"列改为 `[已生成](../references/<ID>.jpg)`。
- [REFERENCE_REVIEW.md](REFERENCE_REVIEW.md)：在"逐卡记录"下追加一节，写明生成工具、尝试次数、实际使用的提示词（与 IMAGE_PROMPTS.json 不同时）、审查结果和裁决建议。
- 一批全部完成后，在 [README.md](README.md) 中更新已生成的数量。

## 验收命令

```
node docs/world/check_kit.mjs          # 本轮结束时必须通过
node docs/world/check_kit.mjs --refs   # 全部 39 张生成完毕后必须通过
```

## 提交

在 main 上提交一次，范围只包含 `docs/world/` 下本轮的参考图和文档更新，然后执行 `git push -u origin main`。推送会触发 Cloudflare 自动部署，但 `.assetsignore` 只发布 index.html，参考图不会公开。

## 不得做

- 不修改任何代码：scene.js、layout.js、buildings/、tools/、build.py、index.html。
- 不修改 WORLD_PLAN.md、WORLD_SPEC.md，以及设计卡的设计内容。
- 不把参考图放进运行页面。
- 不用城镇截图或其他卡片的图冒充本卡的参考图。
- 不一次生成全部 39 张；按批次进行，ST01 之后必须等用户确认。

## 最后回复用户

给出以下内容：

- 本轮生成的卡片和图片路径；
- 每张图的审查结果，以及主要问题；
- 尝试次数，以及与原提示词不同的地方；
- `check_kit.mjs` 的结果；
- 提交链接；
- 下一批卡片编号。
