# CR01 西北圆角残留：根因与执行计划

2026-10-15；W10c 用户截图返工。状态：已实施（第 7 节，PROGRESS「W10c 西北 CR01/RN05 浅角接入返工 实施」），机器检查通过，用户视觉待确认；不启动 W10d、不合并、不推送。

## 1. 位置与纠正

用户总览图的右下角靠近小学 B01-P01。小学坐标为 (-26,-35)，因此该截图方向下的右下角是**城镇西北**，不是地理东南。上一轮“RN04-10 东南圆角”的判断撤回；上一轮在正 x/z 区域的长三角边检查不能作为本问题的排除证据。

目标是 C01-T02 → C01-NW → C01-W-NW 附近：RN04-01 北直段、RN04-18 西北圆角，以及 RN05-01（路线 RN05-RD03，去 LM02 温泉村）。重点世界平面范围 x=[-59,-32]、z=[-60,-48]。节点与道路中线保持原位。

## 2. 已确认根因

### A. 浅角接入的真实交叠超出了固定局部裁切范围

`world.js` 中 RN05-01 从 C01-T02 (-33.117867,-54) 到 LM02-east (-58.430895,-55.777273)，长度 21.270430 m。起始方向与环路北边反向方向只差约 8.35°；支路整幅断面长期贴着环路延伸，经过闭环起点附近仍相交。

`roads.js::prepareCr01Junctions()` 使用：

- `reach = (grid末值 - grid首值)/2 + 2`；此支路为 6.3 m。
- 仅在 `ringS ± reach` 构造 `ringBand`，然后从支路 strip 减去这一个多边形。
- 实际 band 的 x 范围仅约 [-40.596,-25.638]；西北圆角及 x=-46 一带完全不在里面。
- 环路外侧断面让口只取支路前 5 m；接缝顺坡只处理支路前 8 m，且环路里程差不超过 12 m。三套固定范围都不代表真实交叠终点。

结果：RN05 自己的沥青、破损边缘、边沟和草路肩仍叠在 CR01 上，产生近共面的竞争、抬高的碎片及横穿圆角的边界。不能靠删除“杂草”、改变颜色、polygonOffset、降低整个支路或扩大一个矩形遮住来解决。

### B. 描边没有跟随裁切后的表面

`roadkit.js::route()` 生成完整 `lines.edgeL/edgeR`；`roads.js` 渲染 `road:ink:aerial` 时仅按 tunnel 断开，没有应用 CR01 裁切结果。因此即使修复 strip，仍可能保留穿过合并路面的支路边线。RN05 左侧源描边有 36 个采样点落在 CR01 铺装内部，里程 0–17.313141 m。该数字是几何交叠证据，不是“36 个像素可见”的判断。

### C. 检查与实现共享了遗漏范围

`tools/unify_check.mjs` 的 U4-CR01-junctions 用 `j.ringBand` 做包围盒和交叠检查；它只证明实现选中的局部范围已经裁干净。日志“支路全部断面进入 CR01 铺装带 0”容易误读为全环检查，应改为真实全环检查后再使用该措辞。

U2 是路面覆盖/高度检查，并不等价于每个位置只有一个铺装所有者；仅有覆盖通过不足以排除重复面。旧十节点图仍是历史记录，不重写历史通过记录；补记本次发现与其范围局限。

## 4. 实施顺序与约束

1. **先保留失败证据，建立独立检查。** 在当前 W10c 分支检查工作区，保留无关的 `docs/world/WEATHER_COMPLETION_PLAN.md`。运行诊断；扩展 road/unify 检查，从最终实际索引引用的 CR01 铺装三角形重建全环铺装区域，检查所有接入路线完整断面与它的正面积交叠。不可再以待测实现提供的 `j.ringBand` 或“距离路口若干米”作检查范围。边界共边允许，正面积交叠不允许；使用明确的 Float32 数值容差。
2. **以真实扫掠网格求交取代固定长度。** 在 `roads.js` 派生 CR01 铺装区域和支路铺装/完整断面区域，使用空间索引筛选候选三角形/小凸片。保留 CR01 沥青优先：从支路完整断面中减去所有相交的 CR01 铺装；支路有效铺装经过的环路外侧断面要让开。双方侧带交叠也要明确归属并收边，不能留下穿越通行区的排水沟或草肩。
3. **保持曲面与闭环语义。** 使用 strip 的实际 Mercator 顶点及插值属性，不用 `latS()` 的测地偏移替代网格边界；不要对跨圆角的整个区域取单一 convexHull（会填平弯道内侧）。采用三角片/短凸片的并集或等价可靠布尔操作；支持里程跨 0/length，不能在闭环起点截断搜索。现有布局、节点、R8 中线和宽度不变。闭环两端切线存在离散差异，但目前未证明它是本次大面积残留的根因，不顺手重画整环。
4. **顺坡覆盖实际新接缝。** 删除本处对 5/8/12 m 的依赖，按真实相交边界计算连接与过渡；保留现有接缝高度差 ≤0.02 m 的要求。避免给原本正常的其他路口叠加一次坡接。不能通过抬高整条支路覆盖 CR01。
5. **描边、地面裁切与设施同步。** 将支路旧边线在合并铺装内部裁断；对最终输出线段求交，不只是删除几个采样点或整条线。保留真实外边界与无关线。复核 `terrain.js::cutRoads` 的预裁切 footprint：被删掉的支路侧带若不再由其他道路覆盖，不得继续挖掉地形。沿用结构语义（桥下/隧道不误裁）。检查 RN05 路边杂草、草簇、电杆、灯池及电线是否仍侵入合并后的通行区；未证实侵路的物件不删除。
6. **复验后生成交付图并记账。** 更新 PROGRESS 与 ROADMAP，W10c 仍为用户视觉待确认。只提交本任务文件，截图不提交。不合并 main，不推送，不启动 W10d。如需改变冻结中线或移动地标，停下报告，不自行扩大范围。

主要实现文件预计是 `roads.js`；`roadkit.js` 仅在确需输出边界/里程属性时调整；`terrain.js` 仅在最终覆盖与裁切不一致时调整；检查位于 `tools/road_check.mjs`、`tools/unify_check.mjs` 或独立专项工具。不手改 `index.html`。

## 5. 验收清单

- **几何唯一性：** 本处 RN05 完整断面与 CR01 铺装正面积交叠为零，推广至全部接入口和四个圆角；检查最终索引引用三角形，不把未引用顶点计作残留。全环闭环接缝参与检查。
- **实际描边：** 合并铺装内部没有 RN05 残留边线；按最终送往 `road:ink:aerial` 的线段检查。源 `lines` 是否保留可按实现设计决定，不能只让诊断数字变为零。
- **通行与地面：** 合并后铺装无缺面、无额外抬高；连续边界最大高差 ≤0.02 m；铺装外不留由旧 footprint 造成的地形孔洞；合理的外侧排水沟允许存在，但不得横穿通行区。检查平面和球形。
- **设施净空：** RN05/CR01 有关设施与植被不侵入实际通行区；不把正常悬空电线误当路面描边删除。
- **必跑命令：** `python3 build.py`；`node tools/cr01_nw_audit.mjs`；新的完整专项检查；`node tools/road_check.mjs`；`node tools/unify_check.mjs`；`node tools/measure_samples.mjs` 后再 `node tools/layout_check.mjs --png`。若调整地形裁切，另跑 `node tools/terrain_structure_check.mjs`；若改变灯位/光池，另跑 `node tools/streetlight_check.mjs`。报告既有失败与新增失败，不笼统写全通过。
- **性能：** 记录裁切时间/三角面增量及默认视图 calls；默认 calls 增长超过 10% 按仓库规则阻塞。避免每帧求交，全部在构建阶段完成。
