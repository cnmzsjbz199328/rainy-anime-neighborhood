## 4. WX1：修复天气场与确定性（下一步，可立即实施）

目标：同一地点/时间结果与访问顺序无关，空间变化连续，地点限制和既有默认雨仍成立。运行渲染保持不动。

1. 修复缓存：精确坐标计算，或缓存固定格点再连续插值。不能以“用格中心取代第一次坐标”结束工作，因为那仍留下边界跳变。地貌判定缓存与连续场分开，不把冰/沙漠边界随意模糊成禁用天气。
2. 输出六状态权重而非整数相位决定整块天气。空间噪声可保留球面 3D 实现，但用连续权重混合相邻相位；混合后再约束当地允许状态并归一化，保证冰原 rain=0、城镇 snow=0。雪线雨夹雪继续按已有阈值，不改地形雪线。
3. 城镇作为一个天气区：同一 t 城镇 kind=town 取同一场样本；在城外平滑接入连续场。沿用约100 m空间相关尺度，接缝跨经度周期连续。过渡宽度建议先取10 m，属于本计划实施参数，记录实际值及边界扫描结果。
4. 保留六状态、SEED、300 s 时段、至少40 s渐变及启动前300 s城镇默认雨。可以调整连续相位算法，但需重新验证长期占比；不得用永久锁雨掩盖问题。lock 按生物群系合法状态回退，API at/lock/setTime/get 继续可用。
5. 区分稳定的天气时间与动画时间，定义供 WX2 使用的采样接口：sample(lon,lat,t) 返回权重/category；effectsAt 返回 rain/snow/wetness/drip/mist 等物理效果权重，另由表现层应用地图模式、距离与调试开关。湿润与雨击分开，晴夜无雨击、雨后可湿且滴水。不在纯数据模块读取相机、THREE 或 SECTION。

建议新增 tools/weather_field_check.mjs（纯 Node）：

- 同缓存格反向预热、跨类别边界、缓存清理前后、经度±360°、重复查询和不同顺序测试；同点权重误差 ≤1e-12。包含上面的真实反例。
- 权重有限、非负、和为1；冰原无雨、城镇无雪；沙漠长期降雨 ≤5%，允许降雨地貌中雨为最大项且按既有检查 ≥50%（山地计雨+雪）。多点完整周期及6小时窗口都测。
- 时间每1 s采样，权重变化率 ≤1/40 每秒；跨时段首尾均测。城镇网格同 t 权重一致。
- 固定 t 沿相位、城界、海岸、雪线与经度接缝采样；新增平滑带内0.5 m步进最大权重变化建议 ≤0.1，不能只测分类字符串。硬生物群系边界若无法满足，列出反例和边界处理，不能吞掉禁用天气限制。

## 5. WX2：接通全球效果、粒子高度与晴天清理

前置：WX1 机器通过，路灯提交已进入集成工作树。先登记效果清单，分清 rain-impact、wetness、drip、snow、weather-mist、非天气 steam，各项标出拥有者、位置、基值和更新入口。

### 5.1 一个状态来源，按效果所在地采样

雨/雪粒子按其位置或空间块取样，不整箱只用目标点状态；场景总体天空/光照仍允许按观察点采样。海面、水田、道路湿地按表面所在地采样；全球海面禁止仅传相机处一个雨权重给整张海。

大面可使用低分辨率周期天气权重纹理/网格，与纯函数同源，时间插值；无需每粒每帧遍历全部地貌。记录网格分辨率、更新时间与误差，不能新建独立随机天气。球形淡出系数只在最终表现应用一次，避免重复乘导致非线性消失。

uRain 只代表雨击；wetness 单独控制湿润反射/材质；drip 允许雨后延续。旧 SECTION rain 开关保留为测试抑制覆盖时，要明确优先级，不再作为天气真值。不恢复已停用的光带，不改路灯模型或像素 LOD。

### 5.2 雨雪落在正确高度

雨雪箱随目标所在可见地表/水面高度移动，粒子终止于实际接收表面；复用已有渲染地形采样器及道路/桥面查询，不能另造低精度 WORLD.height 贴地系统。桥上、桥下水面、坡地、冰缘分别测试；不把全箱简单抬到山顶而导致低处悬空截断。

遮雨登记包含高度、范围与必要的屋檐，支持城镇和地标；已有8次随机失败后仍落入屋顶的逻辑须有确定性拒绝/跳过处理。避免全屏逐粒射线，使用空间索引/缓存。保留默认城镇雨量、颜色、速度和原有可接受分布；没有必要为修全球高度而重做城镇雨的美术。

雪粒子用 seed+粒子id+时间可寻址轨迹，或提供明确的 reset(seed,t) 用于检查；固定时间重放不能依赖之前帧序。球形所有距离隐藏降水并停止不必要的粒子更新。

### 5.3 统一控制已有天气效果

建筑和地标仅标记/登记滴水、雨流、雪雾等效果，不改建筑结构与位置。LM07 雪雾、城镇雨圈、屋檐滴水、山谷雾带均接天气系数；循环动画每帧不得把系数覆盖回1。非天气生活蒸汽（拉面/温泉等）不得当雨雾全部删除；喷气孔地热蒸汽在 WX3 单独列规则。

球形无降水/天气雾/雨击/滴水；永久冰雪地貌与静态地面材质保留。湿地贴片是否全部消失与晴天无降水不是同一概念，本轮不把海水、稻田或全部静态水洼删掉。

灯光/雾采用明确基值及有序合成，weather 只输出倍率/增量，由现有调用链接收；最小范围消除反馈累乘，不提前实现 W10e 全局 look.js。验证锁定雨→晴→雾→雨与平面→球形→平面恢复，不凭 sync 猜测所有权。

### 5.4 晴天残留雨丝专项（WX-0，优先复现与修复）

用户于2026-10-14补充此实际观察。此前计划覆盖了球形归零及晴夜雨击，但没有单独规定晴夜雨丝检查，现补齐。具体旧画面模式、机位与时间未知；实施者先覆盖下表，不把“自然过渡”当作未经复现的解释。

| 情况 | 明确预期 |
| --- | --- |
| 平面 lock('clear')，下一次天气更新并渲染后 | 所有降水雨丝/雪粒子贡献为0，不受旧 SECTION rain=true 或雨天光照预设影响 |
| 平面自然天气已稳定晴朗（clear权重=1） | 无雨丝；移动、缩放和再次进入该区域不重新出现 |
| 自然雨→晴的渐变期间 | 可随实际rain权重逐渐减少；state仅表示最大权重，不能单凭state='clear'判为纯晴。报告完整权重和剩余过渡时间；结束后必须为0 |
| 球形 uBend=1，任何距离、地点、锁定状态 | 无雨丝或雪粒子；不能以底层天气仍是rain为由放行 |
| 平面↔球形切换中 | 雨丝按既定系数淡出/恢复，端点无残留、首帧无闪回 |

源码线索：scene.js每帧先重设rainMat.opacity，再由weather_fx乘rain权重；平面rainObj.visible没有按零降水隐藏，而section.tick在后面执行。**透明对象visible=true本身不证明能看见雨丝**；应追踪最后一次渲染前的材质值、可见性及所有写入者，核对是否有其他雨线对象、更新次序覆盖、仅切换light预设而未切换天气、state最大权重误判等情况。上述均为待查路径，不能当作已确定根因。

新增明确失败用例：从锁雨切锁晴，默认城镇、城外旧复现点、森林、海岸及冰缘，d=9/40/140/400；再测试晴天冷启动、雨后切晴、解除锁定、平面球形往返和旧rain开关往返。测试必须在最终渲染时捕获降水强度，检查实际所有降水对象。完整零降水时关闭雨丝提交，不能只把一个材质设为0而漏掉其他雨线。

可用确定性同帧自动差分辅助：正常晴天输出与临时强制隐藏全部登记降水对象输出的差异应为0（其他动画/时间完全固定），并记录雨对象绘制情况；此数值结果不代替用户画面验收。檐滴、水面倒影和非天气线条另列，不用“可能只是滴水”直接否定用户观察。WX-0通过前，WX2不能交付为机器通过。

### 5.5 检查与交付

新增/扩展 tools/weather_integration_check.mjs，直接检查页面渲染对象、uniform、粒子范围和注册效果，不能仅断言 get().dry=0：

- 六状态 × 合法地貌；锁晴后海/田/路雨击归零，雨后无雨丝但有湿润/滴水；空间两点处不同天气可同时驱动两处表面。
- 高地、坡道、桥面、海面、LM07、遮雨区的高度与遮雨无穿透；旧城外剔除坐标 [-72,1.2,-12]、[150,1.2,40] 在允许降雨时确有雨对象提交渲染。视锥外对象不作可见性要求。
