# 特定角度／高度灰屏：审查与执行方案

日期：2026-10-15。范围：本轮只审查与制定方案，未改运行源码或 index.html，未推进 W10 阶段。输入为用户提供的灯塔岛两张截图；未打开额外输出作视觉验收。

## 1. 结论与证据等级

**首要原因是全局指数雾在当前观察距离上接近饱和，附加缺陷是加法光池与不受雾影响的墨线没有一致衰减。** 源码与浏览器数值已确认这一机制；用户原截图没有相机参数、天气时间、锁定状态，尚不能宣称精确复现原截图，也不能排除第二个角度相关问题。实施必须先完成下面的固定时间消融实验。

### A. 全局浓雾足以吞掉整幅场景（已确认）

- `scene.js:2`：基础 FogExp2 密度 0.0055。
- `weather_fx.js:15,35–44`：fog 状态增加 0.03 × wLocal，雾色及背景向 `#5a5870` 混合；最高密度 0.0355。
- 本地 `three.min.js` 的 ShaderChunk.fog_fragment：`F = 1 - exp(-density² × vFogDepth²)`，RGB 混向 fogColor。fog_vertex 取 `-mvPosition.z`，即视空间深度。
- 密度 0.0355 时，深度 40 / 60 / 80 m 的雾覆盖约为 86.7% / 98.9% / 99.97%。模型仍参与绘制，但颜色与明暗几乎全部变成雾色。不能仅凭截图把它当成地形消失、裁剪或 WebGL 崩溃。
- `scene.js:329–331` 的 weatherView 平面高度为 camera.y − target.y；相机仰角与距离改变该值，`wLocal(h)` 在 40–120 m 淡出。视空间深度也随观察方向改变，所以雾强弱具有角度与高度依赖。高地使用原始 target.y 而非实际地表高度还存在语义偏差，需单独核验。

浏览器数值实验：当前生成的 index.html，固定天气时间 600 s，锁 fog，目标为 `WORLD.lonLatToTown(190,-8)`（LM08），target.y=1.2、dist=65、yaw=2.5，逐项设置 pitch 并 `__step(3)`：

### B. 亮椭圆：加法光池的雾处理错误（代码确认）

`streetlights.js:420` 的 poolMat 使用 AdditiveBlending，保留默认 fog=true。正常光池通过顶点 RGB 渐暗；标准 fog_fragment 把这些暗色也混向非黑雾色，再做加法混合。浓雾下暗边不再暗，整块光池几何轮廓可能显露为亮椭圆。这与用户第一张图的特征吻合。

`bend.js:80–83` 对加法材质处理的是地图边界雾与球形昼夜淡出，前面的标准 scene fog 仍然会加灰，因此现有逻辑没有解决本问题。

### C. 黑色碎线残留（部分代码确认）

`ocean.js:164` 海岸线与 `landcover.js:695` 林缘线明确 fog=false；主面被雾覆盖后线仍然存在。用户截图里的每一根线尚未逐对象归因，不要把全部墨线一律删除。核查桥索、轮廓壳、地标墨线的材质路径。

### D. 其他路径的优先级

LM08 在 190°、−8°，远离 −85° 地图接缝和极区；边界雾不是该地点的首要嫌疑。bend.js 的 project_vertex 已把最终 mvPosition 交给 fog_vertex，未发现这里使用未弯曲深度的直接证据。海面透明排序、遮挡、相机穿面仍须通过固定机位消融排除；本轮未确认这些是根因。

## 2. 实施步骤（交给执行 agent）

1. **先建立失败证据。** 记录开工 HEAD、工作树、生成物版本；保留已有 WEATHER_COMPLETION_PLAN.md 等未提交工作。新增 `tools/fog_view_check.mjs`，用已完成 worldgen 的页面、确定性时钟与相机。LM08 为主，桥 RN01-07+08+09 为邻近区域；记录 view.get、camera、weather.get、密度、颜色、渲染错误。固定时间依次锁 rain / after / fog / clear；pitch=0.25/0.5/0.8/1.2、dist=35/65/100/160，正反方向各扫一次。测试锁定状态是否实际允许，不能只记录请求字符串。
2. **固定帧消融。** 同一相机和时间，仅将雾密度临时设为 0，直接 render（避免下一帧重新写入）；另做仅光池隐藏、仅海面隐藏、仅海岸线隐藏的对照，并恢复所有状态。比较机器像素差与灰色占比，生成少量本地截图供用户看。若去掉雾仍整屏灰，暂停调雾参数，转查大面积透明面/深度/相机穿入物件，记录实际遮挡对象。不可用临时开关作为交付实现。
3. **先修加法雾。** 加法发光应按透射率 `T=1-F` 衰减 RGB，不能向非黑 fogColor 插值。优先在已有 BEND 材质补丁中按 blending 明确处理标准雾，再保留现有边界衰减及球形淡出。兼容 exp2/linear fog 与无雾材质；不能重复应用雾。检查自定义 onBeforeCompile 链及缓存键。对光池之外的加法材质列清单，验证同样适用；不得简单设 fog=false 让灯光永远穿雾。
4. **修正雾可读性。** 首轮保留 FogExp2，不引入体积雾或另一套渲染路径。依据实际游戏视距减少天气附加密度，或让天气附加光学厚度只累计有限的局地雾路径；先选最小可验证方案。建议试验目标：锁 fog 时主要目标深度 65 m 的透射率至少 0.2，即总 density ≤约 0.0195（仅作为候选调参门槛，最终由用户判断），基础雨夜 0.0055 不动。不得通过永久锁晴/删雾/限制相机角度掩盖。需检查 100–400 m 全景和近地浓雾，避免一个机位通过、其他距离仍全灰。若修改既有 +0.03 规则，同步修改当前规范与天气检查期望，保留历史记录；不能仅把测试阈值放宽。
5. **墨线与高度。** 给应受大气影响的海岸/林缘/物体墨线接入同一雾透射逻辑；保留原设计轮廓强度，避免添加一层补雾。weatherView 高度用明确的实际显示地表/海平面基准核验，保持城镇默认高度与雨夜基线；不要只用未映射的 WORLD.height 代替平面显示高度。此项会影响其他天气效果，须与天气 WX2 负责人顺序集成，避免并发编辑 scene.js/weather_fx.js。
6. **不扩项。** 不修改 layout.js/world.js、道路中线宽度、建筑位置、桥下海床或隧道裁切。不实施整套 WX1–WX3、昼夜循环或 W10d。不改生成 HTML，源码改完由 build.py 生成。

## 4. 用户看点

页面控制台取 `const q=WORLD.lonLatToTown(190,-8)`，设置 `__scene.view.set({mapMode:'flat',target:[q.x,1.2,q.z],dist:65,yaw:2.5,pitch:0.5})`；测试时 `__scene.weather.setTime(600)`、`__scene.weather.lock('fog')`。

1. 灯塔岛与邻桥：浓雾仍存在，但近处桥身、灯塔岛形体可辨，不只剩灰底、硬椭圆和碎线。
2. 同目标 pitch 从 0.25 到 1.2、dist 从 35 到 160 连续移动：变化平滑，不突然整屏变灰；光池随雾变弱，暗边不变成实心圆盘。
3. 切 rain / clear 并切球形再返回：平面雨夜正常，球形始终晴朗白天，返回状态不漂移。

已知待定：原截图的精确相机/时间尚未获得；雾最终浓度与墨线可读性由用户验收。测试结束恢复 `weather.lock(null)` 和 `weather.setTime(null)`（执行前核对 lock 的解锁接口）。

## 5. 审查结论（2026-10-15，执行 agent）

结论：方案的机制判断与源码一致，可以实施；执行时作下列调整，均不改变方案目标与禁止项。

1. **证据核对**：`scene.js:2` FogExp2 0.0055、`weather_fx.js` FOG_ADD.fog 0.03 与雾色 `#5a5870`、three r160 的 `fog_fragment`/`fog_vertex`、`streetlights.js` 光池 AdditiveBlending 且 fog 默认开、`bend.js` FRAG_FOG 只在标准雾之后处理边缘雾与球形淡出，均属实。墨线 fog:false 不止 ocean/landcover 两处：`section.js`（2 处）、`roads.js`（桥索、栏杆、电线等 3 处）、LM06 轮廓线同样如此；城镇建筑墨线 `ink` 与轮廓壳 hull 本来就走普通雾。
2. **第 4 步不能只调常量**：总密度 0.0195 只保证 65 m 处透射率 0.2；同一雾在 100 m 处为 0.026、160 m 处约 0.0001，正是第 4 步自己禁止的“一个机位通过、其他距离仍全灰”。采用该步第一个选项“依据实际视距减少附加密度”：附加密度 ≤ √(−ln 0.2)/d − 基础密度（d 为相机—目标距离，不低于 0）。近处（d ≤ 约 36 m）仍是完整的 +0.03，基础雨夜 0.0055 不变；65 m 处恰为方案建议的 0.0195。
3. **第 3 步编码**：`uBendMat.x` 已用来编码边缘雾模式（edgeFog:false 为 −1），如果用它判断加法，这类材质会漏掉。改为把 `uBendMat` 扩成 vec3，z 单独表示场景雾模式（0 普通、1 加法透射率、2 墨线）。它仍是逐材质 uniform，程序缓存键不变。
4. **第 5 步墨线**：直接打开普通雾会让基础雨夜下的远处墨线变淡，违背“保留原设计轮廓强度”。改为墨线只受天气附加的那部分雾覆盖：F = 1 − exp(−(d² − b²)z²)，其中 b = d − 天气增量；天气增量为 0 时逐位不变。
5. **第 5 步高度**：W8_SPEC 4.3 本来就规定 h 取目标点处地形之上；平面代码用的是未抬升的 `target.y`，高地上会把山高算进相机高度。改用相机所看的 `lookTarget(0)`（渲染地形、海面 0、城镇 1.2 m），城镇内取值不变。WX2 尚未开工（只有 WX1 工作树，改动只在 weather.js），因此不存在并行编辑；WX2 应在包含本提交的分支上集成。
6. **第 2 步截图**：按 2026-10-10 起的规则，视觉验收由用户截图，本轮不生成截图；消融改为同帧像素读回的数字（`--ablation`）。

## 6. 实施记录（2026-10-15，分支 `world/W10c`，开工 `731997f` = 本地标签 `pre-w10c-gray-view`）

- `bend.js`：`uBendMat` 改为 vec3，z 为场景雾模式；FRAG_FOG 先保存雾前颜色，在 three 自身的 `fog_fragment` 之后，加法材质改为“雾前颜色 × (1 − F)”（exp2 与 linear 通用，没有重复施加雾），`userData.inkFog` 材质改为“只混天气增量那部分”。新增全局 uniform `uFogWeather`（`BEND.weatherFogUniform`）。边缘雾与球形淡出逻辑不变；仍是同一个 onBeforeCompile 链和同一个缓存键，没有逐材质着色器补丁。
- `weather_fx.js`：`FOG_SEE = 0.2`；sync 之后把附加密度限制为 `min(FOG_ADD·w·wl, max(0, √(−ln 0.2)/d − base))`，并写入 `uFogWeather`；`get()` 增加 `d` 与 `fogAdd`；视图缺少 `d` 时直接报错（不默默得到 NaN）。FOG_ADD 与雾色不变。
- `scene.js`：`weatherView` 增加 `d`（自由视角为 dist，漫游为相机到行人的距离）；平面 h 改为 `camera.y − lookTarget(0)[1]`；`WEATHER_FX.attach` 传入 `BEND`。
- 墨线：`section.js` 2 处、`roads.js` 3 处、`ocean.js` 海岸、`landcover.js` 林缘、`landmarks/LM06.js` 轮廓线，把 `fog: false` 改为 `userData: { inkFog: true }`。光带、星空、LM07 光环、LM08 光束、雨见岳山雾、LM06 外圈保持 fog:false（发光或特效，不是墨线）。
- 检查：新增 `tools/fog_view_check.mjs`（G1–G4，`--ablation`，`--html` 可指定其他构建）；`tools/weather_check.mjs` C4 按视距上限计算期望并给视图传入 d。
