## 1. 目标、范围与优先级

地图形态（平面 / 球形）与操作方式（自由视角 / 鹈鹕骑行）独立，支持四种组合。骑行中切换地图时，保留同一骑手、同一辆车及其行驶状态，镜头继续跟随。

本计划承接可选 W9b，将原「星球行人视角」明确为「球形骑行与地图切换连续性」。不新增步行系统，不重做 R1–R3，不启动 W10g/W10h，不改变街道中线、宽度、地块、建筑摆放或全球路网。

本计划对 W9b 的模式、进退和切换规则优先于 THIRD_PERSON_ROAM_PLAN 第 2 节、第 6.2 节及 K6 中的「球形不可骑行、切球形退出、恢复旧自由镜头」条款。原文保留为 R1–R3 的历史规格；实施时更新当前用户说明和对应测试，不重写历史验收记录。D9 的球形晴朗白天规则继续有效。

以下是本次交接的实施默认值；实施 Agent 可在不改变用户行为的前提下细化算法，不必逐项重新询问。

## 3. 用户行为

| 行为 | 规定结果 |
| --- | --- |
| 平面或球形自由视角按 V / 骑行按钮 | 从当前观察目标附近的可骑道路进入；沿用最近车行道、桥隧分层与出生提示规则 |
| 骑行中切平面 / 球形 | 不退出、不重新出生；位置、所在层、航向、速度、推车状态、环视偏角及跟随距离连续 |
| 切换约 2 秒期间行驶 | 继续响应骑行输入，运动与主体动画继续；时间不能重复累计或因切换清零 |
| 切换中再次切图 | 从当前弯曲进度反向，不跳到端点，不重置骑行 |
| 骑行拖动 / 缩放 | 拖动只环视，滚轮/双指只调跟随距离；不触发自由视角的转星球 |
| V / Esc / 自由视角按钮退出 | 保持当前目标地图形态，以骑手当前位置为自由观察锚点，不跳回进入前的远处 |
| 切换中退出 | 地图动画继续到当前目标形态，镜头平顺交接到当前位置的自由视角；输入清零 |
| 失焦、页面隐藏或指针取消 | 沿用清输入规则，恢复后无残留油门和转向 |

四个稳定组合均可用。切换中若尚未骑行，可暂时禁用「进入骑行」并提示正在切换；若已经骑行，「退出」始终可用。不得把进入可用性与退出可用性绑在同一个 disabled 条件上。

退出后的自由镜头：锚点取退出时骑手所在道路位置，转换成现有自由镜头的目标语义，保留当前观察朝向，并将距离平顺调到自由视角合法范围；FOV、near 恢复自由视角值。桥梁和隧道须保留所在层的高度信息，不能直接用地表山顶替换隧道内锚点。自由镜头最终落点仍须有效、无遮挡。普通退出建议沿用约 1 秒平滑交接；不得硬跳至远处。这项规则统一适用于平面和球形，取代原逐位恢复进入前镜头的检查。

球形自由视角跨极点的能力保留；球形骑行只覆盖现有可骑路网，不因为自由镜头能到极点就生成极区道路。目标附近没有可骑面时，沿用出生失败处理，并给出可理解的提示。

## 4. 架构与修改要求

### 4.1 一份运动状态与道路数据

继续以现有平面展开坐标保存位置、heading、速度和表面层，复用 ground.js、ride_world.js、ride.js 的道路、接触与碰撞约束。显示阶段才转换到弯曲后的空间。禁止复制第二份球形道路、地面或独立骑行状态。

显示比例 s、纬度、海拔与 BEND 投影共同影响实际显示距离。不能直接把平面镜头偏移当成球面米制距离，也不能未经验证再乘一次 s。记录转换公式及单位，检查城镇、赤道、高纬和高地的速度、轮距与跟随距离。发现现有运动度量与球形显示不一致时，在统一度量接口中修正，不为每条路线写例外。

### 4.2 状态与主循环

- `setMapMode()` 不再无条件 `setRoaming(false)`；切图只改变形态目标。
- 把 `transitionStep()` 从自由视角分支移到共同更新路径，每帧调用一次，并先于最终镜头和天气参数求值。
- 将进入条件、当前骑行状态、退出能力分开；同步按钮、标题、触屏摇杆与测试钩子。
- 指针开始、移动、释放、剩余单指恢复等所有分支都要遵守骑行优先，不能只改 pointermove。
- 骑行位置是跟随镜头与当地天气的锚点；不能继续使用进入骑行之前冻结的自由 target。

### 4.3 镜头与坐标转换

现有 `rideCamera()` 直接使用平面坐标并固定 `camera.up=(0,1,0)`，必须改造。可复用 BEND.point()、BEND.basis() 和 transition.js 的现有能力，建立明确的骑行显示适配接口，至少输出位置、看点、局部上方向及距离/高度度量。

完整球形采用骑手当地坐标框架，镜头的向上方向随所在地变化；平面端点保持现有框架。过渡中对位置、朝向和平滑状态保持一致，使用稳定的正交框架/四元数等处理，特别防止背面或近反向向量线性混合趋于零、镜头翻转、跨经度接缝长距离绕行。不能把完整球面镜头最后一帧才接上。

球形进入骑行的初始航向，从球面观察方向投影到出生点的当地切平面，再转换为骑行 heading；禁止直接相减球面 camera.position 与平面 target。

保留 R2 环视、分轴阻尼、收近/放远、桥面与隧道约束。平面遮挡检查可复用，但不是球面遮挡的充分证明：显示空间的相机—看点直线与平面线段弯曲后的路径不同。增加球面和过渡态的扫掠/遮挡校正，且校正后仍符合所在层净空。机器核对必须使用实际显示变换后的几何；普通 CPU 射线若未计入 shader 弯曲不能作为证据。不得直接套用自由视角的地表抬升，把隧道镜头抬到山顶。

### 4.4 骑手与车

优先沿用全局弯曲管线；确认主体网格、法线、墨线、材质及裁剪均覆盖动态主体。已经由 shader 弯曲的主体不得再对根节点重复做球面投影。

在实际显示空间检查两轮接触、车身俯仰、左右转倾、停车脚、推车与高纬比例。必要修正集中在主体显示适配中，不能改原道路来迁就模型。经度接缝检查必须覆盖车头和车尾分处接缝两侧的情况，禁止把动态人车切成相距一个周期的两半。

主体仍仅在骑行时显示，雨披、车篮与原美术设计保留，不增加光源。

### 4.5 天气与光照

现有骑行 `weatherView()` 写死 `u:0`，且把平面锚点与相机直接计算高度/距离，需要同时修正：

- `u` 读取实际 BEND 进度；所在地从逻辑骑行位置取经纬度。
- 相机高度、相机到观察目标距离使用一致的显示坐标和明确的物理度量；隧道、桥面采用相应层，不能将平面 y 差当球面高度。
- 球形任意距离均晴朗白天，无雨、雪、天气雾、云；切换时沿既有弯曲量规则淡出/淡入。
- 切回平面，恢复骑手当前位置的夜间天气；不重置天气时间，不恢复旧出生点天气。
- daylight、夜间效果、局部雨雪箱和天气查询共同使用当前模式/锚点，不增加骑行专用天气系统。
