## 2. 坐标与单位（W3 的核心约定，必须先读）

W2 的弯曲把「城镇局部平面」按墨卡托映射卷到球面，高度按局部缩放 `s = 1/cosh(z/R)` 同比缩小。为了让地形网格在 `uBend = 1` 时正好落在球面上、在中间值时与城镇一起卷曲，**地形几何用平面（墨卡托）坐标存放，交给 `bend.js` 弯曲**：

| 量 | 公式（R = 90，`TOWN_BASE_HEIGHT` = 1.6） |
| --- | --- |
| 平面 x | `R · lon_rad` |
| 平面 z | `−R · asinh(tan φ)`（北为 −z，与 `lonLatToTown` 一致） |
| 海拔 → 局部真实高 | `y_true = height(lon, lat) − 1.6`（城镇地面 y = 0 对应海拔 1.6 m，海平面是 y = −1.6） |
| 平面 y（存入顶点） | `y_flat = y_true / s = y_true · cosh(z/R) = y_true / cos φ` |
| 弯曲后球半径 | `R + y_true`（W2：`R + y_flat · s`） |
| 法线 | 在局部东、上、南系（x 东、y 上、z 南）里按真实米制梯度算出：`n = normalize(−∂h/∂x, 1, −∂h/∂z)`，其中 ∂h/∂x、∂h/∂z 是 `height()` 对东向和南向真实米的偏导；**不要**再乘 `1/s`；W2 的基底旋转负责把它转到球面 |

要点：

- 海拔 0（海平面）因此在弯曲后位于半径 `R − 1.6 = 88.4 m`；城镇地面在 `R = 90`。world.js 里所有弧长按半径 R 的球面计，W3 沿用（差 1.8% 以内，不另作修正）。
- 平面 y 在高纬度被放大（雨见岳山顶 56°N：24.4 m / 0.559 = 43.6 m）。这只在 `uBend` 小于 1 时可见，而 W3 在 `uBend = 0` 时隐藏远处地形（见 3.5）。
- 平面 z 在 85° 处为 −282 m，夹紧上限 `T_MAX = 8`（`bend.js`）远大于此，数值稳定。
- 经度 ±180° 的接缝：在平面上是 x = ±R·π = ±282.7 m 两条边，几何上重复一排顶点；`uBend = 1` 时两排重合。

## 3. 数据与算法

### 3.1 网格拓扑

纬度环网格：纬度 −85° 到 +85° 之间每隔 **1°**（1.5708 m）一环，第 i 环的经度顶点数 `n_i = max(8, round(2π · R · cos φ_i / 1.5708))`，使球面上相邻顶点距离约 1.57 m；每环的经度原点取 −25°，让雨见岳锚点（56°N 25°W）正好是一个顶点，保证峰值取到 26.00 m。环与环之间用三角带缝合（相邻两环顶点数不同时按弧长比例配对），经度 ±180° 接缝上重复一排顶点。

为什么是 1.57 m：滩坡宽 14 m、山脊半宽 9–14 m、峰半径 12–30 m，最窄的特征横跨 ≥ 12 个顶点；`height()` 的最大二阶导数在滩坡上约 6·1.9/14² = 0.058 m/m²，线性插值误差 ≤ (1.57²/8)·0.058 = 0.018 m。

球面面积 101,788 m²（4πR²）；面积 / 1.57² 约 41.3k 个顶点、82.6k 个三角形，预算 **≤ 90k 三角形、≤ 45k 顶点**（不再单独细分城镇外带或地标：e = 1.57 m 已细于 WC7 的 1 m 网格检查所需，割线坡度不会超过解析最大坡度 4.59%）。

分块：按 15° 经度 × 15° 纬度分块（24 × 12 = 288 块，高纬度块更小），每块一个 `THREE.Mesh`、共享一个材质；包围球用平面坐标算（W2 的弯曲包围球剔除自动适用）。与 TR01 带相交的块拆成两个 Mesh，**共享同一份顶点缓冲**，各用自己的索引：环内三角形（重心的 `townPatchDistance < 24 m`）与其余三角形（见 3.5），这样没有裂缝。

### 3.2 城镇补丁与底座边缘（TR01）

- 地形网格在补丁内部（`|x| ≤ 48`、`|z| ≤ 48`，即 `TOWN_PATCH`）整块丢弃，不渲染。补丁边界上的顶点必须落在补丁边线上（容差 0.01 m），高度 `height = 1.6`（`y_true = 0`）。
- 底座侧面（y 从 −1.6 到 0）因此被地形遮住：地形在边界处与城镇地面等高，向外按 `plain-town` 的 24 m 过渡抬升到周围地形（农田基准 1.9 m、荒野 2.1 m）。
- 不允许出现：悬空的底座、直线硬边、地形与底座之间的缝（W3 检查用补丁边界上的顶点配对）、z-fighting。
- 底座外圈 2 单位的低矮绿化带（现有）保留在补丁内；绿化带在 9 个出口处断开的做法也保留。
- 在 `docs/layout/LAYOUT_V1.md` 末尾追加「W3 底座边缘表现」一节：写明直角切面被 24 m 渐变地形取代、涉及哪些视角、布局数据（道路、地块、设施）未改。

### 3.3 顶点色（W3 只做最小可读）

由 `regionAt` 的区域决定基础色，按 [WORLD_SPEC](WORLD_SPEC.md) 的统一色板取色（夜里偏蓝）；高度与坡度只做明暗（月光方向沿用场景的 `DirectionalLight`）。不做纹理、墨线、细节（W4 的断面与 W6 的地貌负责）。顶点色表：

| kind | 色调（取自 WORLD_SPEC 色板） |
| --- | --- |
| town 外圈、farmland、village、ruin | 低饱和蓝绿到橄榄；遗迹略偏紫灰 |
| forest | 蓝绿、苔绿 |
| grassland | 比森林浅的灰绿 |
| desert | 淡紫灰的沙色 |
| lava | 深炭灰褐 |
| ice-north / ice-south | 蓝白 |
| 海洋三片 | 浅海灰青到深海靛蓝，按海拔（0 到 −6 m）渐变 |
| island | 灰褐岩色 |

### 3.4 极帽

纬度 |φ| > 85° 的两顶小帽用球面坐标直接建（半径 `R − 1.6 + h`，高度取 `height()`），面积各约 0.19%（`(1 − sin 85°)/2`）。它们**不参与弯曲**：给材质一个「不弯曲」开关（`bend.js` 增加 `material.userData.noBend`，程序缓存键相应区分），只在 `uBend ≥ 0.98` 时显示，淡入由 W8 做（ST04：冰盖最后淡入）。W3 中用 `uBend = 1` 的开关直接显示即可。

### 3.5 可见性规则（保持默认画面不变）

| 部分 | `uBend = 0`（默认） | `uBend > 0` |
| --- | --- | --- |
| 补丁外 24 m 的渐变带（TR01，每块的「环内三角形」Mesh，约 20 块、≤ 12k 三角形） | 显示 | 显示 |
| 其余地形（「其余三角形」Mesh）、极帽 | **隐藏**（`visible = false`） | 显示（极帽仅 ≥ 0.98） |

W8 再把「隐藏」换成随距离淡入淡出。W3 的回归规则：`regress.mjs` 与 `pre-w3`（W3 开工前的 main 提交，由 W3 打标签）比较时，只允许距补丁边界 24 m 以内的像素有差异，用遮罩实现；其余像素最大通道差必须为 0（保持 W2 的逐位相同）。

## 6. 性能预算

- 基线（W2 之后，SwiftShader，1280 × 800）：默认视角绘制调用 2361、三角形 237,479；far 9989 / 737,053；top 10,373 / 759,871。
- `uBend = 0`：默认视角绘制调用上升 ≤ 10%（≤ 2597），预期只增加补丁外 24 m 带的约 20 个 Mesh（+0.9%）；三角形上升 ≤ 12k。
- `uBend = 1`：地形 ≤ 288 个块（与 TR01 带相交的块拆成两个 Mesh，最多再加约 20 个）+ 2 个极帽，三角形 ≤ 90k；背面半球不渲染（块的包围球与相机的背向剔除，W2 的包围球剔除已覆盖大部分）。记录 `uBend = 1` 默认视角、far、半球视角的绘制调用与三角形，与 W2 的 bend_check 数字对比；ROADMAP 第 4 节第 6 条适用（`uBend = 0` 默认视角 +10% 为阻塞）。
- 几何与顶点色一次性生成，不在帧循环里重算；生成耗时记录（目标 < 1.5 s，SwiftShader 数字仅供对比）。
