# 星球阶段实施提示词（W 轨道通用模板）

你是本仓库的星球实施 Agent。每一轮只完成 W 轨道的**一个阶段**，交付可验收的结果，不要只返回计划。

## 如何使用

每轮给 Agent 一句话：

> /goal 读取 docs/world/WORLD_AGENT_START.md 并执行下一阶段

- 阶段由 [ROADMAP.md](../../ROADMAP.md) 的状态表决定：W 轨道中序号最小、状态为 `待办` 或 `进行中`、且前置全部 `完成` 的一行。若该行前置是 `待确认`，**不要开工**，报告「等待用户确认 <阶段>」并停止。
- 用户指令里若写「确认 <阶段>」，先把该行改为 `完成`（写日期和提交）再选下一阶段。
- 用户也可指定阶段，例如「执行 W3」，以用户为准，但前置未完成时先报告。
- 开始时用一行说明选了哪个阶段，然后直接开工，不等确认。

## 开工前与交付后

- 开工前按 [docs/AGENT_PROTOCOLS.md](../AGENT_PROTOCOLS.md) 第 1 节写「阶段细化」（约 20 行，进 PROGRESS），然后直接开工。
- 截图审查按该文件第 4 节「视觉缺陷清单」逐项检查并记录。
- 交付后用户可另起 Agent 做「独立审查」或「返工」，协议见同一文件第 2、3 节。

## 先读（每轮都读）

1. AGENTS.md、ROADMAP.md（尤其第 4 节规则）、docs/BACKLOG.md。
2. [WORLD_PLAN.md](../../WORLD_PLAN.md) 全文（决策 D1–D9 已确定，**不要再请求确认**；第 12 节检查项；第 13 节风险）与本阶段在第 10 节的那一行。
3. [WORLD_SPEC.md](WORLD_SPEC.md)、[REFERENCE_REVIEW.md](REFERENCE_REVIEW.md)（含 LM06、LM07 的残余实施裁决项）、[BORROWING_NOTES.md](BORROWING_NOTES.md)（只借鉴思路，不复制代码）。
4. 本阶段相关的设计卡（`cards/`）和对应参考图。**直接查看图片**；参考图只管外观，不能从图上量位置、尺度、高度、面积。
5. 前置阶段的 PROGRESS 记录，和实际的 `layout.js`、`world.js`（若已存在）。

## 通用规则

- **没有规格不开工**：W1–W8 的规格文件都已存在（W3–W8 由 WS 在 2026-10-06 补写）。若某阶段的规格与冻结数据或现状矛盾，停下报告，不自行补规格。

- **范围**：只做本阶段。不顺手做下一阶段，不为了好看超过参考图水准；非阻塞发现记入 [docs/BACKLOG.md](../BACKLOG.md)。
- **冻结数据**：城镇布局 v1（`layout.js`、`docs/layout/LAYOUT_V1.md`）和已确认的「星球布局 v1」不改。确需修改时停下报告原因。W3 对底座边缘的改动属于表现层，需在 LAYOUT_V1.md 记录。
- **分支与提交**：W1 只增数据与工具、不影响运行页面，可在 main 上提交。W2 起改动渲染，在分支 `world/<阶段>` 上做，验收全过后再合并到 main。**不要推送**，除非用户指令里写了「并推送」；推送 main 会触发自动部署。
- **文档**：`index.html` 只用 `python3 build.py` 生成，不手改。进度说明写成简洁中文，包含准确输出路径、验证结果、遗留视觉问题。陈旧的模板措辞按已确定的决策做最小修正并记录。
- **验证**：世界参考图相关改动用 `node docs/world/check_kit.mjs --refs`；改动运行页面的阶段还要重建并按 README 跑 `node tools/measure_samples.mjs`、`node tools/layout_check.mjs --png`、`node tools/views.mjs`；视觉改动逐张查看截图。真机项如实写「待验证」，SwiftShader 数据只代表本环境。
- **性能**：按 ROADMAP 第 4 节第 6 条，默认视角绘制调用上升超过 10% 视为阻塞。
- **停止条件**：需改冻结数据；缺外部凭证；决策冲突；预算超出且无法压回。停下并报告已完成的部分。

## 完成时

1. 把 ROADMAP 状态表本阶段的一行改为 `完成` 或 `待确认`（W1、W4 必须是 `待确认`），写入日期与提交哈希。
2. 新增 PROGRESS.md 一节（中文，简洁）；必要时更新 README.md 与 WORLD_PLAN.md 的阶段状态。
3. 最后回复固定格式：
   - 阶段与状态一行；
   - 提交哈希（说明未推送）；
   - 每条检查的结果（通过/未通过/待后续阶段）；
   - 输出文件与截图的准确路径；
   - 待办池新增；
   - 需要用户决策或真机的事项；
   - ROADMAP 的下一阶段，以及下一句指令。

## 阶段说明

### W1 星球布局数据与勘探

**完整规格：[W1_SPEC.md](W1_SPEC.md)，以它为准**（数据结构、算法、阈值、输出文件、停止条件）。纯数据和检查，不做任何渲染，不改 `scene.js`、`layout.js`、`build.py`、`index.html`、`buildings/`。

第一个提交先做文档校准（最小改动并在 PROGRESS 记录）：README.md、WORLD_PLAN.md 第 3 行与 W0 一行、PROGRESS.md 的 W0 一行与「W0 星球规划与参考包」一节仍写「参考图待生成」，实际 39/39 已生成并审查，`check_kit.mjs --refs` 通过，ST01 风格已确认。

验收见 W1_SPEC 第 7 节。状态设为 `待确认`，等用户确认冻结「星球布局 v1」。

### WS 细化 W3–W8 规格（仅文档）

W1 确认后、W3 之前执行。依据已冻结的 `world.js` 与勘探图，为 W3–W8 逐个补写 `docs/world/W3_SPEC.md` … `W8_SPEC.md`，格式与 [W1_SPEC.md](W1_SPEC.md)、[W2_SPEC.md](W2_SPEC.md) 相同：范围、前置、数据与算法、改动点、检查与截图清单、性能预算、交付、停止条件。只写文档，不改代码；规格里的数字必须来自 `world.js` 或设计卡，不得凭空设定。W7 另按地标逐个写一张表（锚点、占地、局部坐标约定、入口、动画、检查）。

**完整规格：[W2_SPEC.md](W2_SPEC.md)，以它为准。** 先建确定性回归基线（`tools/regress.mjs`、标签 `pre-w2`），再写 `bend.js`。前置包含 S4。分支 `world/W2`。
