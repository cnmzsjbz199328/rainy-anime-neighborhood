## 2. RI-01：骑行开启／退出疑似受区域限制

### 已定位的开启故障（2026-10-21 补充审计）

只读工具 `node tools/ride_entry_audit.mjs`，证据 [audits/ride-entry-2026-10-21.json](audits/ride-entry-2026-10-21.json)。在生成页按 5 单位网格扫描 x∈[SEAM,SEAM+PERIOD)、z∈[-200,200]，出生方向 [1,0]：9,234 点中成功 9,233、失败 1；这是有限采样，不代表其他位置没有故障。

确定复现：

```js
__scene.view.set({mode:"free",mapMode:"flat",target:[191.48231506347656,1.2,-85],yaw:-Math.PI/2,pitch:0.5,dist:34});
// 地图切换完成、至少经过一帧后，点击骑行按钮：仍为 free。
// 同一 target 反向观察（yaw = Math.PI/2）：ground.spawn 的反方向探针可成功。
```

根因链：最近中心线是 RN01-ridge 尾端（RN01-06），里程 58.3969754012 m，中心点 (183.5799846110,15.5784529466)。spawn 再横向偏移 -2.5 m 到 (183.7789653306,13.0852216352)。`point(s,o)` 使用插值切向量构造偏移，但 `project()` 用末段弦方向判断纵向越界，两者在曲线端头不严格互逆；回投得到 `over = 0.0039052253 m`。`candidates()` 对普通道路要求 over ≤ 0，因此拒绝该点；spawn 只试一次就返回 null。反向观察改用另一侧车道则成功。将同一车道候选的 s 内收 0.01 m 后 sample 有效，内收 0.001 m 仍无效。不能据此直接硬编码所有端点内收 1 cm。

**已定位：端点车道偏移与纵向判界不一致导致开启失败；未证实：这覆盖了用户遇到的全部地点或无法退出的现象。**

安全实施边界：在出生候选生成/有效性校验中处理端点几何一致性，按当前道路与车道的实际有效范围确定有效出生站位；保持最近道路、车道方向和桥隧层规则。优先局部修正出生，不通过全局增大 candidates 的 over 容差把不可骑面变为可骑面，不修改道路几何，不伪造 sample、不直接吞错。加入上述确定失败点、反向对照与各类道路首尾探针，修复前失败、修复后通过。

### 退出审计与其余证据边界

用户报告运行时需要到特定区域才能开启、关闭骑行，尚无精确位置、地图形态和输入方式记录。开启已有上述确定缺陷；退出仍需区分用户现象与测试时序，不能把两者混为同一根因。

- scene.js 的 `enterAvailable()` 只要求 ground 已初始化、地图切换结束；`setRoaming(false)` 没有地理范围判断。
- ground.js 的 `spawn()` 按镜头旋转中心 target 寻找全路网最近中心线，无最大出生距离门槛；跳过石阶，隧道内目标改到洞口外，道路宽时选车道偏移。鼠标所指或画面中看到的路不一定是 target 对应的最近道路。
- 最近中心线选定后才检查出生面，若该候选无有效 sample 就返回 null，没有继续尝试其他候选。该失败路径已由上述端点复现证实，但尚不能等同于用户全部现象。
- 退出先调用 `freeExit()` 做镜头反解与避障，再清除 roam 状态；需排查计算耗时、异常、状态与按钮更新，不能只看最终是否有地理判断。
- 当前生成页中上述逻辑与源码一致，但没有读取用户实际运行的浏览器页面，不能据此排除用户页面版本差异。

## 3. RI-02：环视后头颈固定一侧

### 已确认的代码原因

- ride.js 的 `look()` 持续累加 lookYaw，镜头用三角函数计算，因此可绕多圈。
- rider.js 将原始 lookYaw 传给 pelican；rider_pelican.js 用 `clamp(lookYaw * 0.6, -1, 1)` 作为头部偏航目标，并以 lambda 4 阻尼。
- 镜头偏转超过约 95.5° 后头部到达 ±57.3° 上限；累计转满一圈回到相同视角，原始角仍超过上限，头部继续偏向一侧。这是明确的角度周期处理缺失。
- lookPitch 未传给头部，头部俯仰目标固定为 -0.05。这是现状说明，本专项不新增上下追视。

### 实施要求

1. 保留头部 ±1 rad 限幅、0.6 跟随比例与现有阻尼，修复多圈角度造成的固定朝向；不让头部跟随镜头转满 360°，不更改镜头环视手感。
2. 头部目标对 θ 与 θ + 2kπ 应等价。**不能只把角度 wrap 到 [-π, π] 后直接 clamp**：这样会在镜头正前方跨越 ±π 时把头部目标从一侧上限跳到另一侧。应设计连续、周期的受限追视映射，或有连续过渡的背向处理；记录公式、坐标符号与取舍。
3. 前向环视零点头部回中；小角度跟随方向与原行为一致，局部响应接近原 0.6 比例；任意圈数后回到零点应正常回中。跨 ±π 或连绕多圈不突变、不锁死。不能只在 C 回正时重置头部掩盖问题。
4. 骑行、停住、推车、进出骑行及平面/球形/切换中共用同一追视逻辑。不把世界航向或球面坐标直接当成头部局部偏角。
5. 新增机器检查：正负小角、限幅范围、θ 与 θ±2π/±4π 等价、跨 ±π 的连续性、正反连续多圈后回中、C 回正、重复进入。区分目标角与阻尼后的实际角；以实际 pelican.state.yaw 或 head 变换验证，不能只复制公式测试。记录角度与相邻帧最大变化。
