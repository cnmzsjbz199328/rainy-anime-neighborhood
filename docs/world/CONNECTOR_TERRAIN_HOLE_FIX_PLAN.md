## 1. 问题、结论与证据边界

用户提供的截图显示：城镇人行道外缘与环路之间、连接道路两侧出现浅蓝色缺口；用户报告球形状态能看到球对面的底部。

**已确认的缺陷是道路网格裁剪与地形裁切范围不一致。** 连接段两侧旧人行道已从道路网格删除，但地形仍按删除前的完整横断面挖空，留下没有本侧地面的区域。安全修复方向是收回多余的地形裁切，恢复原有地形，不是删除一个蓝色材质对象。

证据等级：

- 源码确认：`roads.js` 删除连接段侧面，`terrain.js` 仍读取旧 `footprint`；具体调用链见第 2 节。
- 浏览器数值确认：九个出口各两侧一个代表点，18 点中 8 点没有命中本侧普通不透明网格，同时全部落在对应道路的地形裁切多边形内。见第 3 节。
- 与用户现象一致：地表开口允许球形视线穿入球体，天空与远侧内容可能透出。
- **尚未确认**：截图每个像素对应的对象、完整空洞面积、球形视线第一命中是否确为远侧地表、其他出口是否存在较窄遗漏。此前没有做完整球面射线检查，也没有对所有侧带进行密集扫描。执行 agent 必须补齐，不能把 18 点抽查写成全量通过或全量缺陷清单。

本轮没有打开额外截图或页面作视觉判断，未修改运行源码，未重建 `index.html`。

## 2. 根因与相关代码

### 2.1 道路的实际面已经缩窄

`roads.js` → `removeTownPavementDuplicates(routes, W)`：

1. 城镇主街、支路按街区岛裁掉重复铺装。
2. 找到位于 `LAYOUT.BASE.half`（当前 ±48 m）的九个出口。
3. 对出口到 `WORLD.roadNetwork.CR01.half`（当前 ±54 m）的连接段，两侧各生成一个矩形。
4. 侧向起点为 `townClasses[edge.class].carriageway / 2 + 0.1`，终点为距道路中线 16 m；调用 `clipStripOutside(rt.strip, polygon)` 删除道路侧面。
5. 当前 `rt.connectorCuts` 只保存出口、方向与裁剪统计；**没有保存 polygon 本身**，执行时若复用该区域，需要增加元数据。

这段代码注释明确说明：目的是移除延伸到城镇外的旧人行道；该行为应保留，不能撤销它来遮住空洞。

`planSteps()` 的顺序为：生成路线 → `prepareCr01()` → `removeTownPavementDuplicates()` → `mergeCr01()`。最终环路与支路还会按实际曲面分配重叠区域，地形修复必须尊重这个最终结果。

### 2.2 地形仍按旧横断面挖空

`roads.js` → `build()` 在完整计划生成后调用 `TERR.cutRoads(DATA)`。

`terrain.js` → `cutRoads(data)` → `routeRow()` 使用 `rt.footprint[i][2..3]` 生成整幅道路横断面范围，再向两侧增加 `CUT_PAD = 0.12 m`；首末端还有 `CUT_CAP = 0.30 m` 的扩展。这里没有读取最终 `rt.strip.index`，也没有扣除 `connectorCuts` 删除的侧带。

因此数据关系是：

```text
旧完整道路横断面 ──→ 地形裁切范围（仍然较宽）
        └──→ 删除侧面 ──→ CR01 合并 ──→ 最终可见道路（已经较窄）
```

地形被删除且道路没有补上的集合，就是缺口的候选区域。不能把整个地形裁切集合直接删除，否则会恢复路面上的草地，并破坏已完成的桥台、隧道洞口处理。

### 2.3 共享裁切的影响

`state.roadPolygons` 同时供 `cutGroundMeshes()` 使用，包括 W4 田面、地表覆盖、部分地标地面。修复必须在这个共享集合形成之前完成，使地形与覆盖面使用同一结果，不能仅给地形事后贴一块补丁。

不要改写完整 `footprint` 的语义：它还服务于设施与植被避让。实际地面替代范围和道路保留净空不是同一个用途，本专项不要求把树和设施重新放进连接段侧带。

## 4. 推荐实现设计

### 4.1 优先采用局部修正，不全局重写道路裁切

建议修改 `roads.js`、`terrain.js`，新增专项检查工具；不改 `layout.js`、`world.js`、建筑、道路线形和 `bend.js`。

1. 在生成 `connectorCuts` 时保存精确裁剪多边形与来源（出口、方向、路线）。直接复用生成道路裁剪的同一 polygon，避免在地形模块另写一套 ±48/±54、半宽和方向推导。
2. 生成该路线的地形裁切多边形时，从旧条带裁切中扣除这些已删除的侧带。处理适用的 route 和 cap 多边形；只处理实际相交的连接段，不波及城镇内街道、桥梁或隧道。
3. CR01、其他道路与路口自己的有效裁切继续加入最终集合。这是“每个来源先修正，再汇总”，不是从全局裁切并集中无条件减去矩形。
4. 不能仅假定第 3 步已经精确：对侧带内全部裁切来源进行审计。检查环路、路口铺装等是否也有超出最终可见网格的扩展；若有，应在本地修正相应来源，不能留下另一个来源继续挖洞。
5. 在局部范围内，将最终道路三角形的投影作为有效覆盖的校验依据。CR01 合并后归另一条道路所有的区域，应由最终道路并集覆盖，不能只对比单条路线。
6. 输出仍写入唯一 `state.roadPolygons`，再运行现有地形与覆盖面裁切流程；保留每个碎片的 `src`、路线与里程，增加出口修正标记和统计，便于追溯。

建议的元数据形式（字段名可随现有风格调整）：

```js
rt.connectorCuts.push({
  exit: id, side: direction,
  polygon: polygon.map(p => p.slice()),
  ...clipStripOutside(rt.strip, polygon)
});
```

### 4.2 特别处理边缘余量

`CUT_PAD=0.12` 与道路保留半宽中的 `+0.1` 不是同一坐标含义，不能直接相减认定还差 0.02 m；道路横断面还涉及 Mercator 缩放和实际网格裁剪。

对连接段边缘至少在 0.01、0.03、0.06、0.12、0.20 m 偏移处取样。若仍有薄缝，应把**本地**地形裁切限制在实际被替代的道路覆盖范围，并根据真实边界插值地形；不能全局清零 CUT_PAD/CUT_CAP，不能通过把地形整体抬高解决。

### 4.3 几何与性能约束

- 原地形的高度、颜色与法线沿原三角形插值，沿用已有多边形差集与插值机制；不要用 `W.height()` 重新采样生成不同曲面的平板。
- 不创建球形专用补面、双层底板、隐藏开关、额外球壳或模式专用 fallback。
- 不恢复旧人行道，不扩大车行道来遮住空洞，不删除海水或改变材质透明度来掩盖问题。
- 不全量将每个最终道路三角形直接注册为裁切多边形，除非局部方案无法正确表达且有性能证据；这会放大地形差集计算和碎片数量。
- 所有处理在构建时完成，不增加逐帧遍历或射线检测。最终道路几何应与修复前一致；本专项改变的是地形及共享地面裁切。

## 6. 专项机器验收设计

建议报告目录 `docs/world/w10c/connector-ground-review/`（再生输出不入库），文件 `report-before.json`、`report.json`、`checks/*.log`。报告保存 HEAD、HTML 哈希、渲染器、页面错误、探针坐标、命中对象、命中距离、裁切来源和失败样本。

借鉴 `tools/terrain_structure_check.mjs`：使用实际显示的三角形和原始地形 chunk；依照顶点着色器顺序处理世界矩阵、接缝位移和弯曲。普通 THREE.Raycaster 不会自动应用 GPU 的 bend 变形，不能拿其原始球形结果作结论。

| 编号 | 检查 | 通过条件 |
| --- | --- | --- |
| CG1 原始缺陷 | 第 3 节固定 18 点，修复前后使用同一工具 | 前四出口原 8 个空点恢复本侧地面；其余点不退化 |
| CG2 完整覆盖 | 数据驱动枚举九个出口，扫描连接段两侧全部原裁剪范围与周围接缝；一般网格 ≤0.25 m，边界另做细偏移 | 应为地面且没有最终道路替代的位置均命中原地形；不能只扫车行道或只扫原 8 点 |
| CG3 道路不被盖住 | 连接段、CR01 交汇处最终道路面及两侧边界密集探针 | 第一有效不透明表面不变成高于路面的地形/覆盖面，无新悬浮或台阶；道路几何保持不变 |
| CG4 弯曲与本侧遮挡 | uBend=0、0.5、1；地形单独检查和全场景局部法线射线检查 | 原地形对应曲面存在；完整球形先命中本侧地面，不把对面地面算作通过；中间态也无新增裂缝 |
| CG5 裁切来源 | 每个失败点/修复区列出所有覆盖它的裁切多边形，比较最终道路并集 | 删除侧带不再被无覆盖依据的裁切挖空；有效道路仍被正确裁地；所有碎片可追溯 |
| CG6 单一显示与冻结 | 比较三种弯曲状态的地形对象、可见性与几何；检查源文件与路线几何差异 | 无模式专用补面/切换；布局、建筑及最终道路不变；页面无错误 |

补充要求：

- CG2 不能把整个 16 m 矩形一概判作必须是草地；里面可能有合法道路、路口、建筑或其他地面。以实际地形基准和最终占地分类，并报告分类数量。
- 球形地面误差容限由原地形三角形和分段弦差推导并写入报告，不用一个大阈值吞掉远侧命中。可复用 TS 工具的近侧距离和参考三角形方法。
- 射线分类识别父链可见性、材质数组及透明特效；海面、光池、涟漪不算不透明封口。地形单独检查不能被树冠或家具碰巧命中替代。
- 保留原始地形参考，不只比较 `terrain.sampler()` 的高度值；高度采样存在不意味着该位置真的有三角面。
- 测试期望由布局数据、原地形及最终显示网格独立计算，不能直接复制新裁切算法来证明自身正确。

## 8. 用户验收看点与交付

以下为建议复核机位，未进行外观验收。进入球形后等切换完成；相机函数使用 `__scene.view.set()`。

```js
// 东侧主街出口 N03：左右缺口原抽查点位于 x=49.5、z=10.5/19.5
__scene.view.set({mapMode:'sphere',target:[49.5,1.2,15],dist:22,yaw:1.57,pitch:0.85});
// 西侧主街出口 N01
__scene.view.set({mapMode:'sphere',target:[-49.5,1.2,15],dist:22,yaw:-1.57,pitch:0.85});
// 东侧支路 N10；西侧 N09 将 target.x 改成 -49.5
__scene.view.set({mapMode:'sphere',target:[49.5,1.2,-15],dist:22,yaw:1.57,pitch:0.85});
```

1. 四个已确认出口：人行道外缘到环路之间恢复连续地面，看不到天空或球对面；左右侧都查看。
2. 同处降低 pitch 到约 0.3 并转动：地形不压路、没有新台阶或细缝。重点看车行道边缘与环路交汇的角落。
3. 其余五个出口：地面和既有道路仍完整，特别是 N04/N08 原来由环路覆盖的点，不应被草地盖住。
4. 相同位置切回 `mapMode:'flat'`：夜景中的地面连续；天气保持既定规则。球形到平面过渡中也没有突然出现的补面。

交付报告必须包含：实际变更文件、提交状态、前后缺面数量、影响面积（若已计算）、检查与性能结果、准确本地证据路径，以及尚待用户判断的草地接缝、色差和路缘外观。机器通过后仍写 **待确认**，只有用户接受才记录视觉完成。
