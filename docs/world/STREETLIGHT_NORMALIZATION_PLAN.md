范围：普通道路灯（城镇、环路、乡道、干道、桥梁和 W4 入口）的模型、登记、照明与显示规则；补齐路灯检查。巷道安防灯、栈道矮灯、石灯笼、航道灯、建筑灯保留用途与造型，不扩展为全世界灯具重做。

冻结：街道中线、宽度、地块、建筑、标线、坡道、水洼和其他设施位置不改。城镇 26 盏普通灯与便利店旧灯的灯位保持；9 盏巷灯不改位置。W4 入口灯保留最近净空修复后的灯位。新灯可在现有路侧合法占地内布置；若必须移动冻结设施或改变田块/地形，报告冲突，不自行扩大范围。

## 2. 已确认的代码问题

- scene.js 的 streetLamp 是独立旧样板：单独几何与 PointLight；普通 26 盏城镇灯是另一段建模代码，使用地面光晕。
- flora.js 的 lamp/lampGlow 是全球道路模型；roads.js 乡道缩放 0.8、bridge.js 桥灯缩放 0.85。section_plan.js 的两盏入口灯由 section.js 另行装配。
- roads.js 的 CR01 长约 374.8 m、没有 furnish；现有 RD03 检查只遍历已配置 furnish 的道路，漏检整个环路。
- 全球道路灯按相机离地高度 40–60 m 退场，城镇/W4 灯不走同一控制；连续光带目前关闭，旧交接仍运行。
- 路灯实例、lampPool 与 rt.lamps 元数据分别筛除，存在失配风险；应在实施时用逐灯记录核对，不能直接宣称已发生失配。

审查基线：node tools/road_check.mjs --no-browser 通过 10 项；此结果不证明灯型、覆盖与视觉通过。

## 3. 本轮实施默认方案

以下是本计划提出的实施参数，供执行与用户看图验收；不得写成历史已确认的视觉裁决。

### 3.1 一套模型和登记

建议新建 streetlights.js，提供纯数据规划与实例化装配接口；模块命名可按现有架构调整，但职责必须唯一。普通道路灯使用同一灯杆/灯臂/灯头几何族、材质、墨线和暖色发光规则；以现有城镇弯臂造型为基础，避免把全球较高灯杆直接搬入城镇。

按用途参数化尺寸：城镇保留约 4.4 m 杆高，乡道/CR01、干道、桥梁分别保留现有全球模型的高度量级（0.8、1、0.85）；用明确杆高与臂长参数表达，不能继续靠来源模块选择不同灯型。统一暖光沿用 #ffd9a0。尺寸值及最终包围盒写进数据报告。

每盏灯至少有稳定 id、路段/节点归属、来源 id、型号、坐标、基底高度、朝向、灯头位置、光池位置、布置或排除原因。旧灯也登记为普通道路灯，保留原灯位和稳定可追溯身份。城镇布局可继续提供权威灯位输入，不建立另一份手工坐标表。

同一份最终灯表驱动灯体、灯头发光、光池及需要的湿地反射关联。装配一次并实例化，删除 scene.js 旧样板道路灯与普通道路灯建模路径、section.js 对普通 lamp 的重复装配，以及被替代的道路灯创建逻辑。巷灯等其他类型继续可用；不得因复用 glow 材质误改建筑灯。

### 3.2 布置与缺灯补齐

- 城镇保持既有灯位及每个地块入口到最近灯 ≤12 m 的既有检查。
- RD01 沿用活动区约 16 m、荒野约 40 m，隧道内无灯；桥梁沿用约 16 m。不重新按每条拓扑边从零起算灯距，跨边/桥头去重。
- CR01 按闭环连续里程约 25 m 一盏、交错两侧规划；闭环首尾间距同样检查。先确定完整可用路侧区间，再排灯，不能仅在路口删除后留下不报告的长空档。
- RD03 沿用约 25 m 与路口/公交站补灯要求；检查所有应布灯的路段，明确城镇出口短接线由相邻灯覆盖还是新增，禁止默认整条路无灯仍通过。RD04/RD05 等不自动套用 RD03 密度。
- 路口、站点补灯与常规灯合并去重；W4 两盏入口灯纳入全网登记后参与覆盖，不再二次添加。
- 先沿线小范围寻位，再尝试另一侧；仍无法满足净空与覆盖则报告坐标、阻挡物和覆盖缺口，不能以“路口已剔除”豁免所有灯距检查。
- 杆基与车行道、路口铺装、坡道、盲道/通行带、边沟、建筑及其他设施不得相交。野外杆基放在完整道路断面之外，额外退让沿用 C01-S 的 0.5 m；城镇使用现有设施带。使用实际杆基包围范围，灯臂可朝向车道但不得碰建筑/电线。新增环路灯不侵入田块、田埂或树干。

### 3.3 照明、投影与远近

普通道路灯统一使用发光灯头和贴地暖光池，不逐灯添加 PointLight；移除旧样板道路灯的独立点光源。迁移前记录其影响，便利店街角作为用户重点验收点。保留建筑自身光源。

光池采样实际道路/地形表面，适应坡道和桥面，限制于接收表面，避免悬空、穿桥与 z-fighting；不得改变现有水洼位置。灯杆按统一米制与经纬投影处理，球形沿当地径向，同一盏灯不生成平面/球形两份模型。

只把普通道路灯纳入共用屏幕像素显示控制，不扩展到建筑/植被的 W10g 合批。移除这批灯按来源或相机高度硬切的规则。建议初始淡出区间为投影杆高 1–2 px（低于 1 px 不显示，高于 2 px 完整，中间平滑/抖动交接），实施时记录投影算法和参数；按同一相机状态计算，不使用观察历史。灯体、墨线、发光与光池同步且无孤立残留。

连续光带保持当前关闭，不为了接替路灯重新启用；离散灯点保留既有用途。球形任何距离均晴朗白天，道路灯自发光、光池和点光贡献为零；实体灯杆可见性由像素规则决定。复用既有昼夜弯曲着色器，不另建昼夜系统。

## 4. 实施顺序（同一专项，顺序完成）

1. 写阶段细化和基线：按来源/路段统计灯数、尺寸、材质、光源类型、显示规则；记录默认与球形性能。保存冻结数据摘要。
2. 建立纯数据灯表与覆盖/净空规划；输出旧 id → 新 id 映射、各路段候选/保留/移除数量、最大间距及原因。先让缺灯检查真实失败，再修复覆盖。
3. 统一普通灯模型、材质和实例化，迁移城镇/旧样板/W4/全球/桥灯；同批删除重复生成路径。
4. 接通统一光池、昼夜和像素显示规则；修复相关反射关联。不要顺手实现 W10e 外观控制器或 W10g 全城合批。
5. 重建、检查、性能复测、交付看点；更新 README、PROGRESS、ROADMAP 和必要的 W10_SPEC 追加专项说明。历史检查记录保留，修改失效检查时写明新旧判据。

## 5. 机器验收

新增 tools/streetlight_check.mjs，报告写 docs/world/w10c/streetlights/report.json；检查不能只检查生成器自己的数量常量，必须对照权威路网、独立距离/碰撞计算及页面实际实例。

- SL1：所有应照明路段有明确策略；CR01 全环覆盖、首尾接续、路口/公交站覆盖。RD03 普通相邻灯距目标 ≤30 m（沿道路里程）；不满足项逐处报告并视为未通过，不能静默豁免。
- SL2：稳定 id 唯一；旧灯迁移无丢失/重复；灯体、发光、光池与最终灯表一一对应。检查不同来源近邻重复、跨节点/闭环重复。
- SL3：杆基净空零冲突；冻结位置/道路/地块/建筑数据不变；复跑城镇入口覆盖和 C01-S 专项。
- SL4：页面只存在一套普通灯几何族和装配路径；尺寸、朝向、贴地与球面径向数值正确。检查桥面/坡地和高纬度，不只平地。
- SL5：同相机重复到访实例/可见结果一致；像素阈值两端及中间没有孤立光池；平面夜间发光，球形贡献为零，切换中无重复灯。
- SL6：无新增页面错误、首帧完整、连续平移/缩放后实例容量不增长；性能符合 W10_SPEC §6。

必跑：python3 build.py；node tools/measure_samples.mjs；随后 node tools/layout_check.mjs --png；node tools/streetlight_check.mjs；node tools/road_check.mjs；node tools/unify_check.mjs；node tools/c01_s_clearance.mjs；node tools/day_check.mjs；node tools/night_check.mjs（不带 --shots）。相关旧灯数/交接断言须按本计划更新，不能删检查掩盖问题。section_check 已知有 RK.chain 失效，不作为通过证据；不要为此扩大重构范围。

性能：node tools/perf_baseline.mjs --views-only --quality high --loads 3 --label w10c-streetlights；JSON 在 docs/world/perf/w10c-streetlights.json。记录 GPU，与本专项开始基线及 pre-w10a 比较。默认中位 ≤17 ms、p95 ≤25 ms、calls ≤2611；首个完整画面 ≤4 s，超过 5 s 按 W10_SPEC 停下报告；球形 d140/d400 相对 pre-w10a 不恶化超过 10%；HTML 增量按 W10_SPEC 的既有基线核算 ≤0.6 MB，同时报告本专项增量。不能把 4–5 s 写成通过，不能用旧性能结果替代本轮实测。

## 6. 用户验收与交付

Agent 不打开最终截图/页面判断外观，不运行截图审查链。可生成少量复现图，放本地 docs/world/w10c/streetlights/，不提交；report.json 也位于忽略目录，关键数字和路径转记 PROGRESS，不强制入库图片。输出机位需记录精确 target、distance、角度、地图模式与天气，避免仅写“环路附近”。

| 看点 | 应看到什么 | 已知需用户判断的变化 |
| --- | --- | --- |
| 默认机位及便利店街角近景 | 普通灯同一造型族，旧样板灯不重复 | 点光源移除后街角受光是否可接受 |
| CR01 俯视及 C01-S 斜视 | 环路连续布灯、路口无侵路、入口不双灯叠放 | 新灯密度和两侧节奏 |
| N01/N03 城镇至干道、C01-T02 至乡道 | 造型连贯，尺寸按用途变化 | 高度变化是否协调 |
| 一处桥头与桥面近景 | 杆脚贴桥面、光池沿坡、不穿桥 | 桥灯尺度与暖光效果 |
| 同目标平面远近推拉及球形 d140/d400 | 灯同步交接，球形晴天不发光 | 远景淡出是否自然 |

交付必须包含提交哈希（未推送）、改动文件、逐项检查结果、按路段灯数与最大间距、性能、精确输出路径、看点和遗留问题。专项完成机器检查后写“路灯专项待用户确认”；W10c 整体原有待确认项保持，不能因本专项通过而宣告 W10c 完成。不开始 W10d，不合并 main。
