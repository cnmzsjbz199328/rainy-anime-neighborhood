# W10c 桥下海床与隧道覆土回归：审查与执行方案

日期：2026-10-15。审查基线：`1381d56`。状态：方案完成，未实施，视觉待用户确认。
本轮依据用户反馈、附图、源码和 git 历史审查；未运行浏览器复现、未打开新截图、未宣称视觉通过。

## 1. 结论与证据

两个问题共用一个根因：道路的二维占地被当成了无限高度的地形删除区域，没有区分贴地道路、桥梁和隧道。

- `terrain.js:348–443` 的 `cutRoads()`：372–375 行遍历所有 route 区间，不判断 `samples[].span`；385–390 行又把全部桥面投影加入裁切。随后对 `state.ring/rest` 实际网格进行 XZ 多边形减法，不判断地形与道路的高度关系。
- `git blame` 确认上述循环均来自 `334dcf86aa6b0ce39fca27d9f3f76d4304ffe2cc`（2026-10-12，W10c 统一道路与清理试验）。该提交为避免地形盖住道路引入全路网裁切，误删了桥下海床与隧道顶部山体；不是最近路灯提交引入的直接变化。
- `roads.js:747` 在构建时调用裁切；`terrain.js:450` 的 `cutGroundMeshes()` 复用同一 `roadPolygons`，影响 `landcover.js`、断面田块及 `scene.js` 的部分地标地面。修复不能只顾主地形而让覆盖面继续按旧规则挖空。
- `ocean.js:15–28,113`：海面由原始地形 chunk 构建，透明且不写深度。海床被删后，水面仍存在，缺少本侧不透明地形遮挡，与用户所述透见球体另一侧现象吻合。具体透出的对象尚未通过运行时拾取确认；透明材质不是已证实的首要回归原因。
- 隧道 `RN01-05` 的定义在 `world.js:677`，区间为该边里程 6.5–29.5 m；`roads.js:850` 起的隧道壳仍存在。图中的外露拱壳与上方地形被纵向裁除一致。

影响不限于球形：裁切发生在投影之前，平面与球形共用受损网格；球形下的穿透更明显。

## 2. 为什么已有检查没抓住

- `tools/unify_check.mjs:405–407`：普通道路探针排除 tunnel/bridge，另有桥面探针，但只验证桥上，不验证桥下海床。隧道顶部没有保留性检查。
- `tools/road_check.mjs:169–178`：隧道覆土通过 `H()` 与拱顶高度比较。`terrain.js:517–520` 的采样器基于原始 chunks，而 `cutRoads()` 修改的是显示网格索引/顶点；有高度不代表还有三角面。
- 因此保留现有 U2 与埋深检查，同时增加“实际显示网格还在”的独立断言。不能以采样器输出或裁切多边形数量代替验收。

## 3. 范围与实现策略

本专项属于 W10c 返工，不启动 W10d–h。不改街道中线、宽度、地块、建筑摆放、全球道路冻结线形或山体高度函数。继续共用一份几何，不增加球形专用补丁、内层遮挡球、独立海床补面或回退开关；不靠调高水面不透明度遮掩缺面。

### A. 先建立失败用例

新增 `tools/terrain_structure_check.mjs`（可复用现有工具的页面启动、弯曲转换与三角面相交算法），先在当前版本记录海床与隧道覆土缺面，再修实现。机器报告写 `docs/world/w10c/terrain-structure-review/report.json`，不入库。明确探针对应边 ID、边内里程、横向偏移、预期表面、实际命中对象/高度。

### B. 按结构语义生成地形裁切区域

1. 保留原有完整道路 footprint，作为路面/路肩及设施避让的数据来源；另从同一份数据派生“需要替代地面的裁切区域”。不把所有使用方的 footprint 一起缩掉。
2. 普通贴地路段沿用当前扫掠网格的精确投影、周期副本、容差与裁切规则，保持 CR01/城镇修复成果。
3. 桥梁跨越段不删除其下地形，移除把整幅桥面加入地形裁切的循环。桥头的贴地引道仍按自身断面裁切；检查桥台端墙、桥墩与恢复地形的连接，不把整段桥下地形挖掉来处理局部接触。
4. 隧道内部保留山体及其地表覆盖；地形裁切在洞口/明挖引道处局部结束。不得把隧道全长 footprint 作为挖山范围。
5. 必须按世界边的准确 span 边界切分跨界采样单元：把 `world.js` 的边内里程正确映射到 route 连续里程，并插值实际扫掠行。不能仅以“区间两端有一个是 tunnel 就跳过”处理，否则 0.5 m 采样边界会残留挖槽或堵路。端帽 `CUT_CAP` 同样受结构边界限制，不能越界重新切入桥下/隧道覆土。
6. 洞口恢复后检查入口：若实际山体三角面封住入口，仅在入口局部按既有洞口轮廓/壳体交线裁剪或重建洞口贴合地形，保留拱顶上方山体。不扩大为沿隧道全长的二维槽；不顺带实现可穿行隧道（当前已有黑色洞口封面）。
7. 复核 junction 裁切是否绕过结构规则；所有裁切多边形记录来源、结构类型与里程范围，方便审计。
8. `cutGroundMeshes()` 使用同一派生地面裁切集合。复核地表覆盖、田块、地标地面消费方；植被/设施避让仍按其净空目的保留原数据，不以本次修复为由重排植被系统。

优先改动 `terrain.js`；只在缺少 span 边界或里程映射时让 `roads.js/roadkit.js` 输出必要元数据，不复制一套路网。无需先改水面材质或 `bend.js`。

## 4. 机器验收

新增检查必须针对裁切后、参与显示的实际三角面；球形检测要应用与 shader 相同的变形和世界矩阵，直接对未弯曲 BufferGeometry 用 Raycaster 不算球形验证。

- **桥下保留**：遍历 `DATA.bridges` 全部桥段，覆盖 RN01-03、07、08、09、13（包含跨接缝段）。沿线不粗于 0.5 m，横向覆盖桥中线、两侧与桥外对照点。隔离地形进行探测，本侧海床/陆地应与裁切前参考网格命中一致；另检查实际场景遮挡。不能把桥面、桥墩、水面或对面半球命中算作海床成功；记录径向/高度误差和近侧命中约束，数值容差由网格及浮点精度给出。
- **隧道覆土**：RN01-05 中段按原地形与拱顶确定应埋藏范围，在中线和拱壳左右取点，必须命中实际山体；沿用现有中段覆土余量 ≥0.3 m、两端外露 ≤8 m 的规则，并检查有效样本数大于零。洞口局部合法开口单独登记，不能豁免整个隧道。
- **洞口与桥头**：隧道两端由外向内的视线/入口净空、引道路面覆盖；全部桥台的贴地到架空交接。兼顾低角度洞口和俯视山脊。区间边界两侧增加密集探针，检查端帽越界和缝隙。
- **模式一致**：平面、球形分别运行；模式切换中间值 0.5 做结构探针，确认没有单独球形补面或网格切换。海水参数、默认雨夜与球形晴天规则保持。
- **既有回归**：`python3 build.py`；依次 `node tools/measure_samples.mjs`、`node tools/layout_check.mjs --png`；再运行新增专项、`node tools/unify_check.mjs`、`node tools/road_check.mjs`、`node tools/terrain_check.mjs`、`node tools/ocean_check.mjs`、`node tools/seam_check.mjs`。若修改覆盖面消费逻辑，加 `node tools/cover_check.mjs`。不缩减 U2 或修改阈值掩盖失败。
- **性能**：同环境比较修复前后冷启动、默认视角与球形 d140/d400 的 calls/triangles/帧时间，使用 README 的 `tools/perf_baseline.mjs`。优先复用已有地形，不增加逐帧处理。默认 calls 增加 >10% 按仓库规则报告阻塞；其他性能差异如实登记。
