# 星球构建规格 v1：雨夜手绘漫画小星球

本规格把城镇的美术语言和细节密度扩展到城镇以外的整颗星球。它是参考图生成和后续实施（W1–W8）的共同依据，不表示任何内容已经实现。城镇本身继续以 [docs/buildings/BUILDING_SPEC.md](../buildings/BUILDING_SPEC.md) 为准。

## 阅读顺序与约束优先级

1. [WORLD_PLAN.md](../../WORLD_PLAN.md)（原则、已确定的决策、坐标、天气、面积预算、目的地、路网）。
2. 本文件。

数值（位置、尺度、高度、面积、坡度）：world.js（W1 之后）> WORLD_PLAN.md > 设计卡 > 参考图。外观：本规格与设计卡 > 参考图。参考图是概念设计，不能从图上量取尺寸；跨视图不一致时以设计卡为准，并在 REFERENCE_REVIEW.md 记录裁决。

## 核心视觉提示词

一颗可以自由旋转和缩放的手绘漫画小星球，像一件精致的收藏模型。现有的日式雨夜城镇坐落在赤道附近，四周是农田和郊外，再往外是森林、山脉、火山、草原、沙漠、海洋和两极冰盖。古老的遗迹散落在森林、沙漠和冰原里，一张道路网把它们和城镇连在一起：城镇附近是铺装路，越往外越粗糙，最后变成土路、石阶、木栈道和雪原上的标杆。

视觉与城镇完全一致：3D 渲染得像 2D 的赛璐璐明暗，深蓝灰或深褐墨线、轻微不规则的线条、克制的纸纹、水彩淡洗、低饱和柔色；线条不能每帧随机抖动。自然地貌不是写实摄影，也不是平涂贴图，而是用团块、轮廓和淡彩表现的立体微缩模型。

氛围：安静、无人、舒缓的夜晚。近处默认下着小雨，与现有城镇一致；拉远到星球全景时天空晴朗、月光明亮。现代文明从城镇向外逐渐退场，自然逐渐接管；遗迹古老而沉默。没有灾难、风暴、喷发或戏剧化的科幻场面。

## 统一色板

| 用途 | 色调 |
| --- | --- |
| 夜色基调 | 冷蓝、灰紫、潮湿石灰；天空与城镇一致（#252e43 一带） |
| 植被 | 低饱和的蓝绿、橄榄绿、苔绿；夜里偏蓝 |
| 水 | 浅海灰青，深海靛蓝；夜里接近天空色，靠反光区分 |
| 土石与沙 | 灰褐、赭石、淡沙色；夜里偏淡紫灰 |
| 雪与冰 | 蓝白，冰隙为浅青蓝 |
| 暖色点缀 | 只来自人的灯光、灯笼、温泉、火山口微光、灯塔；与城镇的暖琥珀同一色系 |
| 隐藏线索的光 | 极淡的冷青白，与所有暖光明显区分，亮度低于任何路灯 |

便利店仍是城镇的主要暖光视觉锚点。温泉村、渔港、灯塔等远处的暖光可以成为星球全景的焦点，但从城镇街道看过去不能抢走便利店。

## 三个观看距离

每个地貌、过渡带和道路都必须在三个距离下分别成立，这是参考图和实施验收的共同标准。

| 距离 | 镜头 | 读到什么 |
| --- | --- | --- |
| 全景 | 星球整体，约 300–400 m 外 | 大色块、海岸线、山脊、夜间光带；细节不可见，但颜色和明暗要有层次，不能是平涂 |
| 半空 | 约 50 m 外的斜俯视 | 地貌结构：林缘、田块、河道、道路走向、地标轮廓 |
| 地面 | 视线高约 1.6–5 m | 材质和细节：树干、苔藓、田埂、浪花、石阶、雨滴落在不同表面上 |

## 墨线规则

- 城镇建筑和近处地标沿用现有的边线描线。
- 地面距离：单棵树、岩石、栏杆、石阶描边。
- 半空距离：只描林缘、田埂、海岸、道路边缘和地标轮廓，不描单棵树。
- 全景距离：只描海岸线、山脊和冰缘的外轮廓。
- 星球的外轮廓（与天空交界处）保留一条连续的深色墨线，让星球像一个微缩模型。
- 墨线颜色和粗细在全星球统一，深蓝灰为主，不同距离之间平滑过渡，不跳变。

## 光与天气

时间固定为夜晚（D9）。天气由观看距离、时间和位置共同决定（D8，详见 WORLD_PLAN.md 第 4 节"天气"和 ST05 天气状态板）：

- **全景距离总是晴朗月夜**：无云、无雨，有星星。月光和环境光比近处更亮，属于"可读性光照"，保证从星球外能看清所有地貌、道路和地标；但仍然是夜晚的冷色调，不能变成白天。
- **近处和行人视角是局部天气**：雨（默认）、雨后、阴、晴夜、雪、雾，按时间缓慢切换，并由所在位置决定可能出现哪些天气。城镇的默认状态与现在完全一致。
- **中间距离平滑过渡**：雨丝、云层和光照随镜头距离逐渐变化，不突然切换。

光源：

- **月光**：主方向光，冷色，从高处斜射；山脊、浪尖、湿润树冠有月光边缘光。
- **人工光**：路灯（只在 RD01、RD03 和地标入口）、村落窗光、灯笼、灯塔。使用自发光材质与贴图光斑表现，避免大量实时光源。
- **自然光**：火山口极弱的红光、温泉蒸汽被灯光照亮、少量萤火虫（只在遗迹附近）。
- **雨**：近处沿用现有的雨丝和水洼系统，只在镜头附近下。
- **雪**：冰盖和雪线以上用雪代替雨，交界处为雨夹雪。

参考图中，所有"全景"格画晴朗月夜，半空和地面的夜间格画该地点的局部天气（默认是雨）。

## 动态规则

- 每个地貌系统或地标最多 1–3 处主要动态，动作要轻、慢、随机错开。
- 动态必须按距离分级：全景用缓慢的纹理流动或明暗呼吸，半空用几何的轻微起伏，地面用细节动画（涟漪、滴水、叶片摆动）。
- 禁止：闪烁的灯、剧烈的波浪、喷发、高速移动的物体。

## 尺度

| 对象 | 尺度 |
| --- | --- |
| 统一比例 | 1 单位 ≈ 1 m，与城镇相同 |
| 门、台阶、栏杆、长椅 | 与城镇建筑相同的人体尺度，不缩成玩具比例 |
| 树 | 灌木 0.5–1.5 m；杂木 4–7 m；杉树 8–12 m |
| 地形高度 | 见 WORLD_PLAN.md 第 4 节；高度可以夸张，但人造物的尺度不夸张 |

## 细节层级与性能

- 树木、岩石、稻架、标杆等重复物件必须实例化；同一种物件共享几何和材质。
- 全景距离只显示星球表面的纹理和地形，不加载 3D 物件。
- 背向镜头的半球不渲染 3D 物件。
- 每张卡在"细节层级与性能"一节给出预算；超出预算时先减少物件种类和密度，不降低近处的质量。
- 软件 WebGL 的帧时间只代表本环境，真机性能保留为待验证。

## 数据与集成

- W1 之后 world.js 是星球的唯一数据来源；场景代码和检查工具都从中读取。
- 城镇的 layout.js 与布局 v1 保持不变。
- 地标使用局部平面坐标（前方 +Z，原点在主入口），在 world.js 中登记锚点经纬度、朝向和底面高度。
- 道路、河流、海岸线在球面上定义，沿曲线生成横截面。
- 新增源码文件必须同步 build.py，保持最终单文件 HTML 可离线打开，不依赖外网。

## 统一验收

每个地貌、过渡带和道路的实施都要附上：

1. 三个距离的夜间截图（全景为晴朗月夜，半空和地面为默认的雨），加一张其他局部天气的截图，以及半空距离的中性光截图；
2. 与相邻地貌、道路的交界处截图；
3. 动态在三个距离下都在动，且符合动态规则；
4. 星球检查 WC1–WC14 继续通过，现有城镇检查继续通过；
5. 绘制调用、三角形、实例数和纹理的增量；
6. 更新设计卡的实施记录和 PROGRESS.md。

地标沿用逐栋建筑的验收方式：四立面、总平面、剖面、雨夜斜视、远眺的实景截图，以及锚点、朝向、高度的检查。
