# 画面验证责任与交付流程统一计划

状态：已执行（2026-10-11）；文档修订与检查记录见 [PROGRESS.md](../PROGRESS.md)「视觉验收责任与交付流程统一」。

## 1. 目标

统一本仓库各轨道、阶段和参考图流程中的画面验收规则：默认由用户本人完成所有需要人眼判断的画面验证。Agent 负责按规格修改代码或资产、构建、运行本阶段要求的机器可判定检查，并交付精确的人工看点清单。

只有用户在具体任务中明确主动要求 Agent 做某项画面验证时，Agent 才执行该项验证。没有说明、过去做过、工具默认生成截图、或某份旧文档要求 Agent 看图，都不构成例外授权。例外只覆盖用户点名的任务和验证内容。

本计划是流程与文档整理，不授权更改场景代码、画面设计、布局数据、测试阈值或阶段范围。执行本计划的独立 Agent 只改指引和计划涉及的任务记录；不替用户检查画面，也不执行任何场景视觉验收。

## 2. 统一术语与责任边界

### 2.1 用户负责的画面验证

凡结论需要人看图片、截图、视频、实时页面或图像生成结果后判断，即属于画面验证，默认由用户完成。例如：构图、可读性、风格、物体是否自然落地、遮挡、接缝、闪烁、雨线穿插、建筑细节、参考图符合度、视觉缺陷清单、截图对比和联系表审查。

Agent 不得自行查看运行结果或生成图像后宣布“视觉通过”“画面正常”或据此把用户验收闸门标为完成。它应把视觉状态写为“待用户验收”。

### 2.2 Agent 可负责的机器检查

Agent 仍须运行当前阶段规格明确要求、且能以数据或程序规则判定的检查，例如：拓扑与连通性、坐标和尺寸误差、碰撞与净空、实例数量与路径确定性、布局冻结校验、控制台错误、绘制调用、三角形数、帧时间、文件体积、自动像素逐位比较和其他明确阈值。

机器生成的像素差、指标或截图存在性检查，只能作为自动化数据结果报告，不能代替用户对外观、风格或画面质量的判断。不要因为某个脚本能生成很多截图，就默认必须运行其全部截图序列。

### 2.3 参考图与视觉输出

- Agent 可按规格读取参考图，作为实现输入；这不等于对最终画面的验收。
- 如果阶段必须生成截图或图像文件作为交付物，Agent 可按阶段要求生成并报告准确路径，但默认不打开这些输出作人工判读。仅在用户要求时才由 Agent 检查图像内容。
- 不为 Agent 自审而生成截图审查链、联系表、前后对比图、逐张截图或浏览器视觉巡检。已有检查工具若同时承担机器检查与截图输出，只运行本阶段需要的部分；无法分离时，报告其输出副作用，不对输出作视觉结论。
- 参考包的结构、数量、尺寸、元数据和文件完整性仍可由 `check_kit` 等程序检查；图像内容是否符合设计由用户判断。

## 3. 每轮 Agent 工作流程

1. **确认当前阶段与范围**：读取 `ROADMAP.md`、该阶段规格、`PROGRESS.md`、`README.md` 和本阶段入口指引。先确认阶段的通过条件，不能仅按某个工具的默认完整模式推断范围。
2. **实施与构建**：按规格修改源文件并使用规定命令构建；不得手改生成文件或扩大到相邻阶段。
3. **选择机器检查**：逐项对照本阶段退出标准，只运行相关检查。命令带有 `--only`、`--views-only`、`--no-shots` 等筛选项时，显式选择当前阶段要求的范围；避免因不带参数而跑入其他阶段的长序列。
4. **记录结果**：用中文列出实际运行的检查、结果、数值、输出路径、未通过项与环境限制。清楚区分机器通过、机器未通过、未运行和待用户验收。
5. **交付人工看点**：按第 4 节给出可复现的位置和预期。只覆盖本轮改动及其关键相邻区域，不要求用户复查无关画面。
6. **等待用户验收**：若 `ROADMAP.md` 或阶段规格要求用户确认，保持 `待确认`，不得提前标成 `完成` 或越过确认闸门。用户明确确认后再按既定流程更新状态。

## 4. 人工看点清单格式

每轮交付应提供短而可操作的清单。每个看点尽量包含：

- **位置/机位**：场景名称、方位、朝向、平面或球形模式、缩放距离；如需从默认机位操作，写清操作步骤。
- **检查目标**：本轮具体改动在画面上应呈现什么，以及需要观察的相邻连接、遮挡或轮廓。
- **预期与已知差异**：期望结果；已明确留给后续阶段处理的现象，避免被误报为本轮缺陷。
- **打开方式**：当前构建入口或用户可直接使用的页面；只有阶段要求或用户需要截图时才附截图路径。

建议格式：

| 看点 | 机位与操作 | 应看到什么 | 已知暂留项 |
| --- | --- | --- | --- |
| 示例 | 平面夜景；从城镇默认视角转向 N08 并向南 | 出口道路沿指定方向连接，关键设施位置不变 | 路口铺装属于后续阶段 |

交付摘要不得写“视觉通过”。推荐写法是：“机器检查均通过；以下画面待用户验收”，并附清单。

## 5. 执行本计划时需要整理的文档

独立 Agent 先搜索现行入口和未完成阶段中关于截图、看图、视觉审查、联系表、截图审查链的命令式措辞，再按本计划统一。优先检查：

1. `AGENTS.md`：写入仓库级默认规则、授权边界、机器检查与人工画面验收的区分。
2. `docs/AGENT_PROTOCOLS.md`：把“独立审查”和视觉缺陷清单改为机器审查与用户视觉验收分工；不得要求独立 Agent 逐张查看截图。
3. `docs/world/WORLD_AGENT_START.md`、`docs/world/IMAGE_AGENT_START.md`：统一星球实施和参考图工作中的输出检查与用户验收规则，保留按设计输入读取参考图的要求。
4. `docs/buildings/AGENT_START.md`、`docs/buildings/SAMPLE_UPGRADE_AGENT_START.md`、`docs/buildings/SAMPLE_REVIEW_AGENT_START.md`：去掉默认由 Agent 逐张看实景截图的要求，提供面向用户的看点交接。
5. 当前未完成阶段的规格、`ROADMAP.md`、`README.md` 与活动中的 `PROGRESS.md` 检查清单：修正会让 Agent 默认跑截图审查链或超范围默认测试的现行指令。

历史 `PROGRESS.md` 中已完成阶段的审查记录属于事实档案，不因新政策而重写，也不要求对历史画面重新验收。若某个已完成阶段日后重新开工，以新的用户指令和仓库级规则为准。

### 已知需要对齐的例子

- `docs/world/W10_SPEC.md` 已规定 W10 画面由用户验收，Agent 只跑数据检查并交付看点清单；该边界应与通用入口保持一致。
- `docs/world/WORLD_AGENT_START.md` 对旧阶段仍有“逐张查看截图”的规则。后续尚未完成的阶段应改为由用户验收，不能以旧模板覆盖新默认。
- `docs/buildings/AGENT_START.md` 与样板升级入口仍要求 Agent 查看生成截图，需按默认用户验收改写。
- W10b 的 `PROGRESS.md` 重跑清单列出不带参数的 `node tools/lod_check.mjs`；而 `W10_SPEC.md` 对本轮要求 L1/L2。整理时应将命令写成 `node tools/lod_check.mjs --only L1,L2`，避免无意跑 L3/L4/D3。只有单独任务明确要求完整 W8g 检查时才运行那些项目。

## 6. 不改动的边界

执行者不得：

- 修改 `scene.js`、建筑/地标/地貌代码、布局或道路数据、`index.html`、构建脚本或测试阈值。
- 为了简化流程而删除规格要求的数据检查、性能预算、确定性像素比较、布局测量或用户确认闸门。
- 改写已完成阶段的历史结果、视觉裁决或截图证据。
- 删除或覆盖已有图片；不得把忽略目录下的审查截图纳入提交。
- 代替用户打开页面、检查截图、评判风格，或在最终回复中声称已完成视觉验收。
- 顺手执行正在进行的 W10b 代码返工、停止其他进程、合并分支或推送。

本计划只要求更新持久指引和必要的活动阶段命令，不授权改变艺术目标、场景内容或阶段状态。

## 7. 执行顺序

1. 检查 `git status`，保留工作区现有改动；确认新旧指引和当前未完成阶段。
2. 用 `rg` 搜索命令式视觉审查措辞，例如“逐张查看”“直接查看截图”“亲自查看”“视觉缺陷清单”“截图审查”“contact sheet”“review screenshots”。逐条分类为：实现输入、机器检查、用户画面验收、历史记录。
3. 先修改仓库级规则与 `docs/AGENT_PROTOCOLS.md`，建立唯一的默认分工和授权标准。
4. 再更新世界、参考图、建筑、样板升级入口与当前活动阶段的冲突指令；示例命令显式限定本阶段范围。
5. 复查所有改动处的相对链接、规则优先级和状态词；确认旧的“Agent 必须目视检查”没有留在活动入口中。
6. 检查 `git diff --check`、`git status --short` 与最终 diff。只提交本计划授权的文档文件；是否提交遵从用户实际执行指令和仓库分支流程。
7. 最终交付文档改动路径、搜索和修订范围、保留的机器检查、修正的命令、仍需用户视觉验收的入口，并明确没有执行场景画面验证。

## 8. 完成标准

- 新 Agent 只读 `AGENTS.md` 与对应阶段入口即可知道：用户默认拥有所有需要人眼判断的画面验收。
- 唯一例外是用户对当前任务明确、主动授予 Agent 的指定视觉检查；授权不扩展到其他镜头或阶段。
- Agent 仍按阶段规格运行必要的机器检查，并且不因工具的默认完整模式运行无关序列。
- 所有活动工作流都能给用户可复现的短看点清单，并明确已知暂留问题。
- 历史视觉记录和图像资产未被重写或删除，场景源码、布局数据、测试阈值和性能预算未改变。
- 文档之间不再有要求 Agent 默认检查最终画面的矛盾指令。
