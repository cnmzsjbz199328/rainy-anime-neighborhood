# 首版布局 v1（冻结）

本文件记录 P4 冻结时的道路与地块坐标，以及之后的变更规则。坐标的唯一来源是 `layout.js`；本文件中的表格由 layout.js 生成，供审阅和对照。完整检查明细见 `docs/layout/layout-report.md`（由 `node tools/layout_check.mjs` 重新生成）。

坐标约定：X 正向为东，Z 正向为南，Y 向上；1 单位约 1 米；底座 96 × 96，范围 [−48, 48]。

## 1. 规划要点

- **骨架先于建筑**：三条道路走廊均为 12（车行道 + 设施带 + 净宽 2 的人行道），两个十字路口 X01（信号控制）、X02（R02 优先、R03 停车让行）。路灯、电杆、信号灯、标志和雨水篦子都放在设施带内，人行道净宽始终保持 2。
- **六个街区、38 块地块**：35 块预留，3 块已有样板。各街区按用途分档：
  - B01：学校用的整块大地块；
  - B02：住宅组团，北排经 A03 内巷进出；
  - B03：沿主街的邻里商店，南面一排是公共设施和口袋公园；
  - B04：交番、诊所、小神社，以及公交站后的口袋公园；
  - B05：便利店街角和已有样板；
  - B06：沿主街的商住楼，南排为住宅，经 A02 进出。
- **为将来的建筑留够空间**：
  - 每块地块都有退界和可建范围。场景中，预留地上的浅色碎石面就是可建范围。
  - 检查 C11 会给每块预留地试排一栋该用途的典型建筑及其附属设施，全部放得下，且建蔽率 ≤ 60%，才算通过。附属设施包括：停车位（只能接主临路边）、后勤/垃圾、自行车棚、学校操场等。
- **步行优先**：
  - 8 处斑马线两端都是 1:10 无台阶坡道；
  - 内巷口和学校车辆入口只在设施带内降坡，人行道保持水平连续；
  - 内巷、W01 通道和公交候车区与人行道齐平；
  - 38 块地块都能经连续的人行面到达（C6）。
- **基础设施走廊**：
  - 电杆和电线沿 R01 北侧、R02 西侧、R03 南侧的设施带布置，单跨不超过 30。
  - 边沟沿所有直线路缘连续，篦子间距 ≤ 15。路面雨水和内巷暗沟都排到底座边缘的出口。

## 4. 变更规则

1. **新建筑只占用已有地块**：
   - 先选一个预留 plotId，把建筑放进该地块的可建范围（`buildable`），包括阳台、檐口、外置楼梯。入口朝向该地块的 `front`。
   - 附属设施（停车、后勤、自行车）留在地块内。停车位接主临路边。
   - 新建筑在 layout.js 的 `buildings` 中登记放置变换、实测包围盒和遮雨区（`samples` 只留给三栋旧样板），并把地块状态改为 `occupied`、`building` 指向它。
   - 门落在地块既定入口上：入口位置决定路灯、电杆的避让区，门位偏移会移动街道设施（C12 检查）。
   - 重新运行 `measure_samples.mjs` 和 `layout_check.mjs`（C12 检查实测模型），全部通过后再单独提交。
2. **可以局部调整地块分割**：
   - 同一街区内，可以合并、拆分地块，或微调边界和入口位置，但不得越过街区边界，也不得压到内巷、通道或候车区。
   - 调整后 C3–C7 和 C11 必须通过。v1 中已做过两处这样的调整：B04-P01/P02 改为 10 + 10；B05-P07/P08 入口改到东侧。
3. **内巷与人行通道**：可以在街区内调整，但必须保证 C6（每块地可达）和 C9（巷口降坡）通过。
4. **主要道路（R01–R03）、交叉口、街区边界和标高（`LEVELS`）冻结**。如确需改动：
   - 先更新 ROAD_NETWORK_PLAN.md，说明理由；
   - 再改 layout.js，全部检查重新通过（C1–C11）；
   - 重新生成 `live-topdown.png` 和 `views/` 截图并逐张查看。
   - 标线、坡道、边沟、篦子、路灯、电杆和水洼都由道路数据派生，会自动跟随，不要在 scene.js 中手工补坐标。
5. **街道设施**：
   - 新增或移动路灯、电杆、标志，只放在设施带或巷边，并且不压斑马线、坡道和地块入口（C10）。
   - 新建筑如果遮挡路灯，按 C10 重新检查入口照明。
